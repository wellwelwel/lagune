# /lagune-repair: ซ่อมการติดตามข้อตรวจพบที่เสียหาย

> ซ่อมห่วงโซ่เมื่อการเปลี่ยนชื่อหรือย้ายไฟล์ทำให้การติดตามของ Lagune สับสน

ภาษา: th-TH
ต้นฉบับ: https://lagune.ai/docs/commands/repair
อัปเดตล่าสุด: 2026-11-07

🧰 ซ่อมห่วงโซ่เมื่อการเปลี่ยนชื่อหรือย้ายไฟล์ทำให้ห่วงโซ่สับสน

**งานบำรุงรักษาภายใน ไม่ใช่เฟสด้านความปลอดภัย**

repair ไม่ใช่เฟสที่ 6 ในเวิร์กโฟลว์ที่เรียงตามลำดับ หน้าที่ของ repair คือรักษาการติดตามให้สอดคล้องกัน

```prompt
# ไม่ต้องใส่อินพุต: ซ่อมทั้งห่วงโซ่เสมอ
/lagune-repair
```

## หลักการทำงาน

ข้อตรวจพบแต่ละรายการจาก detect คือรายการที่ติดตามหนึ่งรายการ ซึ่ง plan, harden และ verify ส่งต่อกันไป แต่ละเฟสจัดการกับรายการนั้นและรายงานกลับด้วยชื่อของรายการ ชื่อนี้เขียนเหมือนกันทุกตัวอักษรเป็นหัวข้อของส่วนในทุกอาร์ติแฟกต์ และเป็นตัวตนของรายการนั้นตลอดทั้งห่วงโซ่

สิ่งเดียวที่เปลี่ยนแปลงได้ง่ายซึ่งการติดตามเก็บไว้คือ path ของไฟล์ที่รายการชี้ไป path เหล่านี้ไม่ได้อยู่ที่อื่น การเปลี่ยนชื่อหรือย้ายไฟล์จึงทำให้ลิงก์ขาดได้เฉพาะที่นั่น และไม่มีทางเกิดสำเนา 2 ชุดที่ไม่ตรงกัน เมื่อเกิดเหตุนี้ repair จะแก้แผนผัง (`.lagune/tracking.json`) เพื่อให้ตัวตนของรายการยังอยู่หลังการเปลี่ยนชื่อ repair อ่านอาร์ติแฟกต์และแผนผังการติดตาม อ่านซอร์สโค้ดของคุณเพียงเพื่อหา path ใหม่ของไฟล์ที่เปลี่ยนชื่อ และไม่เขียนเนื้อหาด้านความปลอดภัยใดเลย

ในรอบเดียวกัน repair จะตรวจอาร์ติแฟกต์ความจำทุกรายการเทียบกับเทมเพลตของตัวเอง และรายงานส่วนที่คลาดเคลื่อน โดยชี้แต่ละรายการไปยังเฟสที่ต้องแก้ไข

**เคล็ดลับ**

- repair ไม่แตะต้องทั้งโค้ดของคุณและอาร์ติแฟกต์ที่เป็นเนื้อหา แตะเฉพาะการติดตาม
- คุณแทบไม่ต้องรันเอง เมื่อเฟสใดพบว่าห่วงโซ่ไม่สอดคล้องกัน เฟสนั้นจะรัน repair ให้คุณแล้วทำงานต่อ
- การติดตามที่ repair ดูแลอยู่ที่ `.lagune/tracking.json` ซึ่งเป็นสถานะภายในที่คุณไม่ต้องแก้ไขเอง

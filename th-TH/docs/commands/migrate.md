# Migrate: ย้ายโปรเจกต์ Lagune แบบ manifest ไปใช้ skill และปลั๊กอิน

> ย้ายโปรเจกต์ Lagune แบบ manifest ไปใช้ Lagune แบบ skill โดยเก็บ charter อาร์ติแฟกต์ การติดตาม และความรู้เฉพาะทางของคุณเองไว้ครบ

Canonical: https://lagune.ai/th-TH/docs/commands/migrate
ภาษา: th-TH
ต้นฉบับ: https://lagune.ai/docs/commands/migrate
อัปเดตล่าสุด: 2026-11-07

🔀 ย้ายโปรเจกต์ **Lagune** แบบ manifest ไปใช้ **Lagune** แบบ skill โดยเก็บทุกอย่างที่คุณเขียนไว้ครบ

**ประกาศเลิกใช้**

โปรเจกต์ที่มี manifest ยังทำงานได้ตามเดิมจนถึง `v1.x`: `npx lagune` ส่งต่อ `init`, `pull`, `update`, `add`, `remove`, `list` และแดชบอร์ดไปให้ `lagune@0.15.0` ซึ่งเป็นเวอร์ชันสุดท้ายที่ใช้ manifest

## วิธีย้าย

1. ตรวจให้แน่ใจว่า commit งานปัจจุบันแล้ว จากนั้นรัน migrate จาก root ของโปรเจกต์:

   ```bash
   npx lagune migrate
   ```

2. commit เฉพาะสิ่งที่ migrate เปลี่ยน เพื่อให้การย้ายเป็นการเปลี่ยนแปลงเดียวที่ตรวจทานได้
3. ติดตั้งคำสั่งสำหรับเอเจนต์ของคุณตามที่ [หน้าการติดตั้ง](https://lagune.ai/th-TH/docs) แสดงไว้
4. ถ้าโปรเจกต์มีอาร์ติแฟกต์ของ detect, plan หรือ harden อยู่แล้ว ให้ขอ [`/lagune-repair`](https://lagune.ai/th-TH/docs/commands/repair) ปรับการอ้างอิงแบบเดิมในอาร์ติแฟกต์เหล่านั้นและในความรู้เฉพาะทางของคุณเองให้ตรงกับสภาพปัจจุบัน:

   ```prompt
   /lagune-repair ปรับ applied specializations (ชื่อเดิมคือ sub-skills) ในอาร์ติแฟกต์ใต้ `.lagune/memory/` (`detect.md`, `plan.md` และ `harden.md`) ให้ตรงกับชื่อที่แคตตาล็อกใหม่แสดง และเขียนทุกการเรียกที่ความรู้เฉพาะทางของฉันใน `.lagune/catalog/` ใช้เรียก hook เดิมใน `.lagune/hooks/` ใหม่ ให้เป็นการเรียก tool `lagune_read` หรือ `lagune_write`
   ```

## สิ่งที่เปลี่ยนไป

| ก่อน                                                                    | หลัง                                                                          |
| ----------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `.lagune/templates/`, `.lagune/hooks/` และ `.lagune/specializations.md` | ลบออก: แต่ละ skill มีเทมเพลตของตัวเอง และเอนจินเป็นผู้รัน hook                |
| สำเนาของความรู้เฉพาะทางในตัวที่อยู่ใน `.lagune/skills/`                 | ลบออก: เอนจินเป็นผู้ให้บริการรายการในตัว                                      |
| ความรู้เฉพาะทางของคุณเองใน `.lagune/skills/`                            | ย้ายไปที่ `.lagune/catalog/`                                                  |
| `.lagune/skills.json` ซึ่งเป็นดัชนีความรู้เฉพาะทางของคุณเอง             | รวมเข้าใน `.lagune/configs.json`                                              |
| หมวดหมู่ใน manifest                                                     | บันทึกไว้ใน `.lagune/configs.json`                                            |
| คำสั่งเอเจนต์แบบเดิม เช่น `/lagune.detect`                              | ลบออก: [การติดตั้ง **Lagune**](https://lagune.ai/th-TH/docs) จะเพิ่มคำสั่งใหม่ เช่น `/lagune-detect` |
| บล็อกของ **Lagune** ใน `.gitignore`                                     | ลบออก พร้อมลบไฟล์ด้วยถ้าไม่มีอะไรอื่นอยู่ในไฟล์                               |
| `.lagune/proofs/` ที่บล็อกนั้นละเว้นไว้                                 | กันไว้นอก commit ด้วย `.gitignore` ของตัวเอง                                  |
| `.lagune/manifest.json`                                                 | ลบทิ้งเป็นลำดับสุดท้าย                                                        |

งานด้านความปลอดภัยของคุณยังอยู่ครบตามเดิม: charter อาร์ติแฟกต์ที่แต่ละเฟสสร้างขึ้น และแผนผังการติดตามพร้อม path ที่ข้อตรวจพบแต่ละรายการชี้ไป

## คำถามที่พบบ่อย

### ต้องย้ายโปรเจกต์ไหม

ต้อง โปรเจกต์แบบ manifest เลิกใช้แล้วและทำงานได้ถึง v1.x เท่านั้น ให้รัน npx lagune migrate เพื่อย้ายโปรเจกต์ของคุณ

### migrate เก็บอะไรไว้บ้าง

charter ของคุณ อาร์ติแฟกต์ของทุกเฟส แผนผังการติดตาม หมวดหมู่ของคุณ และความรู้เฉพาะทางของคุณเอง ความรู้เฉพาะทางจะย้ายไปที่ .lagune/catalog/ และดัชนีของความรู้เหล่านั้นจะรวมอยู่กับหมวดหมู่ของคุณใน .lagune/configs.json

### ควรติดตั้งคำสั่งใหม่เมื่อไร

หลังรัน migrate ตามที่หน้าการติดตั้งแสดงไว้สำหรับเอเจนต์ของคุณ จะติดตั้งก่อนก็ได้เช่นกัน เพราะ migrate เก็บ /lagune ตัวใหม่ไว้

### เพื่อนร่วมทีมย้ายโปรเจกต์ไปแล้ว ต้องรันอะไร

pull การย้ายนั้นมาก่อน แล้วรัน npx lagune migrate หนึ่งครั้ง คำสั่งนี้จะลบสิ่งที่ Lagune แบบ manifest ทิ้งไว้ใน clone ของคุณ ซึ่ง version control ไม่เคยเก็บไว้ และกันการพิสูจน์ของคุณไว้นอก commit

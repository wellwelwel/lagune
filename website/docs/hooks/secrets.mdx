The `secrets` hook flags **credentials compiled into the source** instead of read from the environment, and **credential and environment files Git tracks**, such as a private key, a **Terraform** state, or a `.env` that sets a secret. In the code, it keys on **provenance** (a literal versus an environment lookup), not on the value's contents, so it needs no exhaustive catalog of provider prefixes and produces almost no false positives. It is the deterministic engine behind the [`secrets` specialization](/docs/catalog).

Provider-format signatures, connection-string credentials, and a literal bound to a secret-named identifier are **language-agnostic**: the same string reads the same in any file. The two heuristics that depend on syntax, an environment lookup with a hardcoded default and a secret flowing into a log sink, are **language-aware**, so a JavaScript `console.log` is never read on a Rust file and Python's `os.getenv("X", "default")` is seen on its own.

## Run it

```bash
npx lagune read secrets                  # scans the whole project
npx lagune read secrets --dir src        # scans a directory
npx lagune read secrets --file config.ts # scans a single file
```

The scan prints up to three sections. **Hardcoded secrets found** is the finding set (a hardcoded default for a secret-named environment variable, a credential embedded in a connection string, a value matching a curated provider format, a credential file **Git** tracks, or an environment file **Git** tracks that is meant to stay local or sets a secret), so the hook exits non-zero. **Secret handling to review manually** is a lead set: a plain literal bound to a secret-named identifier (its provenance is decidable, but whether the value is a real secret is not), a secret-named value flowing into a log or response sink, and a credential or environment file whose **Git** status or content the hook could not read. **Secret handling advisories** leaves the exit code alone: any other environment file **Git** tracks. A clean run prints `no hardcoded secrets found`.

### CLI options

| Option   | Value       | Description                                                       |
| -------- | ----------- | ----------------------------------------------------------------- |
| `--dir`  | a directory | Scope a scan to a directory. Repeats and combines with `--file`.  |
| `--file` | a file      | Scope a scan to a single file. Repeats and combines with `--dir`. |

With no option it scans the whole project.

### Choose what it scans

It leaves out what **Git** ignores. To leave out more, or to scan what **Git** ignores, give `secrets` settings of its own:

```bash
npx lagune write add --ignore test/fixtures --checker secrets
```

```json
{
  "checkers": {
    "secrets": { "gitignore": false, "ignore": ["test/fixtures"] }
  }
}
```

[Configure the hooks](/docs/hooks/configure) covers every setting.

### Credential files under version control

A file that exists to hold a credential is matched by its name, the same in every language, and by what it holds where the name alone cannot tell. The hook reads **Git**'s own index to learn whether **Git** tracks it, without running **Git**.

| File                                 | Names                                                                                                                                              | Reported when                                                                                  |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Private key                          | `*.key`, and `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519` with their `_sk` forms                                                                   | Always                                                                                         |
| Private key                          | `*.pem`                                                                                                                                            | It holds a private key block                                                                   |
| Keystore                             | `*.p12`, `*.pfx`, `*.jks`, `*.keystore`                                                                                                            | Always                                                                                         |
| Cloud or service account credentials | `credentials.json`, a name ending in `-credentials.json`, `_credentials.json`, or `.credentials.json`, `service-account*.json`, `.aws/credentials` | Always                                                                                         |
| **Terraform** state                  | `*.tfstate`, `*.tfstate.backup`, `*.tfstate.<timestamp>.backup`                                                                                    | Always                                                                                         |
| Registry auth token                  | `.npmrc`                                                                                                                                           | It sets `_authToken`, `_auth`, or `_password`                                                  |
| Registry auth token                  | `.pypirc`                                                                                                                                          | It sets a `password`                                                                           |
| Kubeconfig credentials               | `kubeconfig`, `kubeconfig.yaml` or `kubeconfig-<name>.yaml`, `*.kubeconfig`, `.kube/config`                                                        | It embeds a `token`, a `password`, a `client-key-data`, or an auth provider's secret or tokens |

A value left as a placeholder, such as `${NPM_TOKEN}` or `<your token>`, sets nothing. A credential file **Git** tracks is fixed by untracking it with `git rm --cached` and adding it to `.gitignore`, since an ignore rule alone never untracks a file, and one that **Git** ignores or does not track stays silent. Without a **Git** index the hook can read (outside a repository, in a worktree or submodule whose `.git` is a file, or with an index it cannot parse), every credential file present is a lead instead, since a missing answer never reads as clean.

### Environment files under version control

An environment file is `.env` or a `.env.<variant>` file, never a source file such as `.env.ts`. **Next.js** and **Vite** commit `.env` files with public defaults on purpose, so the content of a tracked one decides what it is.

| Environment file **Git** tracks                                                | Result   |
| ------------------------------------------------------------------------------ | -------- |
| A variant meant to stay local, such as `.env.local` or `.env.production.local` | Finding  |
| One that sets a secret                                                         | Finding  |
| Any other one                                                                  | Advisory |
| A template: `.env.example`, `.env.sample`, `.env.template`                     | Silent   |

A line sets a secret when it gives a value to a variable named like one, such as `DB_PASSWORD`, `JWT_SECRET`, `GITHUB_TOKEN`, or `STRIPE_API_KEY`, or when it holds a value in a curated provider format, even in a comment. An empty value, a placeholder, a reference such as `$OTHER` or `${OTHER}`, and `true` or `false` set nothing, and a variable **Next.js** (`NEXT_PUBLIC_`) or **Vite** (`VITE_`) ships to the browser on purpose never counts by its name alone. A finding is fixed by moving the secret to a local variant **Git** ignores, or by untracking the file with `git rm --cached` and adding it to `.gitignore`. An environment file **Git** ignores or does not track stays silent, and without a **Git** index the hook can read, a local variant or one that sets a secret is a lead.

### Language coverage

The environment-fallback finding and the log-sink lead read a per-language set of forms, so they cover the languages below and stay silent elsewhere. The other three signals run on **every** file.

| Signal              | Languages                                                                       |
| ------------------- | ------------------------------------------------------------------------------- |
| Environment default | JavaScript/TypeScript, Python, Ruby, PHP, Kotlin, Java, Go (`cmp.Or`), Rust, C# |
| Log / response sink | JavaScript/TypeScript, Python, Ruby, PHP, Java, Kotlin, Go, Rust, C, C++, C#    |

:::note[Is this a policy problem?]

No. Detecting a secret's format to warn that it was committed is standard defensive tooling, the same operation **gitleaks**, **trufflehog**, and **GitHub** push protection perform. The hook ships detection signatures (public token **formats**), never a live secret, and it audits and explains rather than exfiltrating.
:::

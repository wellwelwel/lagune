The `secrets` hook flags **credentials compiled into the source** instead of read from the environment, and **credential and environment files Git tracks**, such as a private key, a **Terraform** state, or a `.env` that holds a secret. In the code, it keys on **provenance** (a literal versus an environment lookup), not on the value's contents, so it needs no exhaustive catalog of provider prefixes and produces almost no false positives. It is the deterministic engine behind the [`secrets` specialization](/docs/catalog).

Provider-format signatures, connection-string credentials, and a literal bound to a secret-named identifier are **language-agnostic**: the same string reads the same in any file. The two heuristics that depend on syntax, an environment lookup with a hardcoded default and a secret flowing into a log sink, are **language-aware**, so a JavaScript `console.log` is never read on a Rust file and Python's `os.getenv("X", "default")` is seen on its own.

## Run it

```bash
npx lagune read secrets                  # scans the whole project
npx lagune read secrets --dir src        # scans a directory
npx lagune read secrets --file config.ts # scans a single file
```

The scan prints up to three sections, each weighed by its evidence:

| Section                                | Means                         | Exit code |
| -------------------------------------- | ----------------------------- | --------- |
| **Hardcoded secrets found**            | Proof of an exposed secret    | Non-zero  |
| **Secret handling to review manually** | A plausible, unconfirmed risk | Unchanged |
| **Secret handling advisories**         | A real risk not exposed yet   | Unchanged |

A finding is a hardcoded default for a secret-named environment variable, a credential embedded in a connection string to a remote host, a value matching a curated provider format, a credential file **Git** tracks, or an environment file **Git** tracks that proves a secret. A lead is a plain literal bound to a secret-named identifier, in the code or in an environment file (its provenance is decidable, but whether the value is a real secret is not), a connection string to a local database, a secret-named value flowing into a log or response sink, a credential file the hook cannot confirm or that sits in a test folder, and what the hook could not read. An advisory is a secret **Git** would commit with the next `git add`, or a local environment file **Git** tracks or would commit. A look-alike stays silent, and a clean run prints `no hardcoded secrets found`.

### CLI options

| Option   | Value       | Description                                                       |
| -------- | ----------- | ----------------------------------------------------------------- |
| `--dir`  | a directory | Scope a scan to a directory. Repeats and combines with `--file`.  |
| `--file` | a file      | Scope a scan to a single file. Repeats and combines with `--dir`. |

With no option it scans the whole project.

### Choose what it scans

It leaves out what **Git** ignores. To leave out more, or to scan what **Git** ignores, give `secrets` settings of its own:

```bash
npx lagune write add --ignore test/fixtures --checker secrets
```

```json
{
  "checkers": {
    "secrets": { "gitignore": false, "ignore": ["test/fixtures"] }
  }
}
```

[Configure the hooks](/docs/hooks/configure) covers every setting.

### Credential files under version control

A file that exists to hold a credential is matched by its name, the same in every language, and by what it holds where the name alone cannot tell. The hook reads **Git**'s own index to learn whether **Git** tracks it, and the ignore files **Git** reads to learn whether **Git** ignores it, without running **Git**. That answer holds even when the hook's settings scan what **Git** ignores, or when a scan names the file.

| File                                 | Names                                                                                                                                              | Reported when                                                                                  |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Private key                          | `id_rsa`, `id_dsa`, `id_ecdsa`, `id_ed25519` with their `_sk` forms                                                                                | Always                                                                                         |
| Private key                          | `*.key`, `*.pem`                                                                                                                                   | It holds a private key block, and as a lead when it holds nothing the hook recognizes          |
| Keystore                             | `*.p12`, `*.pfx`, `*.jks`, `*.keystore`, except **Android**'s `debug.keystore` and a truststore                                                    | Always                                                                                         |
| Cloud or service account credentials | `credentials.json`, a name ending in `-credentials.json`, `_credentials.json`, or `.credentials.json`, `service-account*.json`, `.aws/credentials` | Always                                                                                         |
| **Terraform** state                  | `*.tfstate`, `*.tfstate.backup`, `*.tfstate.<timestamp>.backup`                                                                                    | Always                                                                                         |
| Registry auth token                  | `.npmrc`                                                                                                                                           | It sets `_authToken`, `_auth`, or `_password`                                                  |
| Registry auth token                  | `.pypirc`                                                                                                                                          | It sets a `password`                                                                           |
| Kubeconfig credentials               | `kubeconfig`, `kubeconfig.yaml` or `kubeconfig-<name>.yaml`, `*.kubeconfig`, `.kube/config`                                                        | It embeds a `token`, a `password`, a `client-key-data`, or an auth provider's secret or tokens |
| **dotenvx** private keys             | `.env.keys`                                                                                                                                        | It sets a `DOTENV_PRIVATE_KEY`                                                                 |

A value left as a placeholder, such as `${NPM_TOKEN}` or `<your token>`, sets nothing. A **Keynote** deck saved as `.key`, or a `.key` or `.pem` holding only public blocks such as a certificate, stays silent. **Android**'s `debug.keystore` is insecure by design, with a password **Android** publishes, and a truststore holds only public certificates, so neither is a credential file. A credential file earns only its own verdict, never a second entry from the scan of its content.

A credential file **Git** tracks is fixed by untracking it with `git rm --cached` and adding it to `.gitignore`, since an ignore rule alone never untracks a file. One that **Git** neither tracks nor ignores is an advisory, since the next `git add` commits it, and one that **Git** ignores stays silent.

A credential file in a test folder (`test`, `tests`, `testdata`, `fixture`, `fixtures`, `spec`, or `specs`, at any depth) is a lead instead of a finding or an advisory, since a test suite often carries a key made for it. When it is made only for tests, leave its path out in the [project's configs](/docs/hooks/configure). The hook never leaves one out on its own.

### Environment files under version control

An environment file is `.env` or a `.env.<variant>` file, never a source file such as `.env.ts`, a template such as `.env.example`, `.env.sample`, or `.env.template`, or the **dotenvx** `.env.keys` credential file. **Next.js** and **Vite** commit `.env` files with public defaults on purpose, so the strongest evidence a file holds decides what it is, and one **Git** ignores stays silent:

| What the file holds                                             | **Git** tracks it | **Git** neither tracks nor ignores it |
| --------------------------------------------------------------- | ----------------- | ------------------------------------- |
| A proven secret                                                 | Finding           | Advisory                              |
| A possible secret                                               | Lead              | Lead                                  |
| No secret, in a local variant such as `.env.local`              | Advisory          | Advisory                              |
| No secret, in a shared file such as `.env` or `.env.production` | Silent            | Silent                                |

A secret is proven by a value in a curated provider format, even in a comment, or by a connection string with a real password to a remote host. It is possible when a variable named like a secret, such as `DB_PASSWORD`, `JWT_SECRET`, `GITHUB_TOKEN`, or `STRIPE_API_KEY`, holds a value: its name cannot tell a real credential from a development default, so it earns the same lead as that literal in the code. A connection string to a local database, on a loopback address, `0.0.0.0`, **Docker**'s `host.docker.internal`, or a single-label host such as a **Docker Compose** service, is a possible secret too. A local variant holding no secret is still an advisory, since the next secret written there lands in a commit.

An empty value, a placeholder such as `changeme`, `<your token>`, or `sk-...`, a reference such as `$OTHER` or `${OTHER}`, `true` or `false`, a plain number under a token name, such as a token limit, and a value **dotenvx** encrypted set nothing. A variable a framework ships to the browser on purpose never counts by its name alone:

| Prefix         | Framework                |
| -------------- | ------------------------ |
| `NEXT_PUBLIC_` | **Next.js**              |
| `NUXT_PUBLIC_` | **Nuxt**                 |
| `EXPO_PUBLIC_` | **Expo**                 |
| `PUBLIC_`      | **SvelteKit**, **Astro** |
| `VITE_`        | **Vite**                 |
| `REACT_APP_`   | **Create React App**     |
| `VUE_APP_`     | **Vue CLI**              |
| `GATSBY_`      | **Gatsby**               |

A value in a provider format still proves a secret under any of them. Each entry names the variables behind it, never their values. A finding is fixed by moving the secret to a local variant **Git** ignores, or by untracking the file with `git rm --cached` and adding it to `.gitignore`.

### When Git's state cannot be read

The hook reads **Git**'s state only from inside the project. Without an index it can read there, such as in a worktree or a submodule whose index lies outside the project, in a folder that is not the repository's root, or with an index it cannot read, whether **Git** tracks a file is unknown. Since a missing answer never reads as clean, the hook then prints one lead that names the cause and what to do, never one per file, and a credential or environment file joins it only when it would be a finding or a lead if **Git** tracked it.

### Language coverage

The environment-fallback finding and the log-sink lead read a per-language set of forms, so they cover the languages below and stay silent elsewhere. The other three signals run on **every** file.

| Signal              | Languages                                                                       |
| ------------------- | ------------------------------------------------------------------------------- |
| Environment default | JavaScript/TypeScript, Python, Ruby, PHP, Kotlin, Java, Go (`cmp.Or`), Rust, C# |
| Log / response sink | JavaScript/TypeScript, Python, Ruby, PHP, Java, Kotlin, Go, Rust, C, C++, C#    |

:::note[Is this a policy problem?]

No. Detecting a secret's format to warn that it was committed is standard defensive tooling, the same operation **gitleaks**, **trufflehog**, and **GitHub** push protection perform. The hook ships detection signatures (public token **formats**), never a live secret, and it audits and explains rather than exfiltrating.
:::

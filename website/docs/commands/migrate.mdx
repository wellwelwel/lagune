🔀 Move a project the **Lagune** CLI installed to the skills-based **Lagune**, keeping everything you wrote.

:::note[For projects with a `.lagune/manifest.json`]
Earlier versions installed **Lagune** with `npx lagune init`, which wrote the commands, templates, and hooks into your project and recorded them in `.lagune/manifest.json`. **Lagune**'s commands now install through the [**skills.sh**](https://www.skills.sh/wellwelwel/lagune), and `.lagune/` holds only your project's own state.
:::

## Nothing forces the move

A project with a manifest keeps working as it is. `npx lagune` hands `init`, `pull`, `update`, `add`, `remove`, `list`, and the dashboard to `lagune@0.15.0`, the last version of the **Lagune** CLI, and prints a notice pointing here. What only the skills-based **Lagune** has (the hook subcommands, `catalog`, and the `--categories` flag) fails in such a project instead of reaching that version.

## Move it

1. Make sure your current work is committed, then run migrate from the project root:

   ```bash
   npx lagune migrate
   ```

2. Commit what it changed on its own, so the move stays one reviewable change.
3. Install the commands:

   ```bash
   npx skills add wellwelwel/lagune
   ```

   Or paste this prompt into your agent:

   ```md
   Run `npx --yes skills add wellwelwel/lagune` and follow the generated skill instructions now. Read its complete output, redirecting it to a temporary file first if necessary. Resolve relative paths from the supporting-files directory it provides.
   ```

4. Rerun [`/lagune-detect`](/docs/commands/detect) before resuming harden or verify on findings detected before the move, so their applied specializations are named the new way.
5. If one of your own specializations calls a hook, rewrite the call with the engine command, since `.lagune/hooks/` is gone:

   ```bash
   # Before
   node ./.lagune/hooks/regex.mjs --dir src

   # After
   npx --yes lagune regex --dir src
   ```

:::tip[Migrate first, install second]
Migrate removes the agent commands the manifest lists, and the old `/lagune` sits where the **skills.sh** installs the new one. Installing first means installing twice.
:::

## What changes

| Before                                                                   | After                                                                                                                 |
| ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `.lagune/templates/`, `.lagune/hooks/`, and `.lagune/specializations.md` | Removed: each skill carries its template, and the engine runs the hooks                                               |
| The copies of built-in specializations in `.lagune/skills/`              | Removed: the engine serves the built-ins                                                                              |
| Your own specializations in `.lagune/skills/`                            | Moved to `.lagune/catalog/`                                                                                           |
| `.lagune/skills.json`, the index of your own specializations             | Merged into `.lagune/configs.json`                                                                                    |
| The manifest's categories                                                | Recorded in `.lagune/configs.json`                                                                                    |
| The agent commands the manifest lists, such as `/lagune.detect`          | Removed: the [**skills.sh**](https://www.skills.sh/wellwelwel/lagune) installs the new ones, such as `/lagune-detect` |
| The **Lagune** block in `.gitignore`                                     | Removed, with the file when it held nothing else                                                                      |
| `.lagune/proofs/`, ignored by that block                                 | Kept out of commits by its own `.gitignore`                                                                           |
| `.lagune/manifest.json`                                                  | Deleted, last                                                                                                         |

Your security work stays as it is: the charter, the artifact each phase produced, and the tracking map with the paths each finding points at.

:::tip

- It touches only **Lagune**'s own files and the agent commands the manifest lists, never your code. A manifest entry that is not a **Lagune** command, or points outside the project, is left alone.
- It refuses to start when the manifest, `.lagune/skills.json`, or `.lagune/configs.json` is not valid JSON, so it never guesses which specializations are yours or which categories you use.
- An own specialization whose destination in `.lagune/catalog/` already exists stays in place, and migrate reports it for you to reconcile.
- The manifest goes last, so an interrupted run leaves the project on the **Lagune** CLI, ready to migrate again.
- Without a manifest, there is nothing to migrate, and it says so.

:::

Install the plugin from your terminal, then approve it, since **Muse Code** starts the plugin's engine only once you do:

```bash
muse plugins marketplace add lagune wellwelwel/lagune#plugin-muse
muse plugins install lagune@lagune
muse plugins approve lagune
```

Start a new session to load it, from your project's folder: the plugin's engine serves the folder **Muse Code** starts in, even when `--workspace` names another.

## Update

**Muse Code** leaves the plugin at its installed version until you update it. To update **Lagune**, refresh the marketplace, then install and approve the plugin again:

```bash
muse plugins marketplace update lagune
muse plugins remove lagune
muse plugins install lagune@lagune
muse plugins approve lagune
```

## Commands

Type the commands by their names, such as `/lagune-charter`. **Muse Code** also lists them under the plugin's name, such as `/lagune:lagune-charter`, and both forms run the same command.

---

:::info[Permissions]

The plugin carries **Lagune**'s engine and runs it outside **Muse Code**'s sandbox, through two tools: `lagune_read`, which only reads your project and runs without asking, and `lagune_write`, which changes only its `.lagune/` folder. **Muse Code** reviews each `lagune_write` call, or asks you under "Ask me", and "Always allow" keeps it allowed.

Where the engine runs through **npx** instead, the sandbox keeps **npm**'s cache read-only, so the engine cannot be downloaded inside it. Install the engine in your project from your own terminal, once and again after each update:

```bash
npm i -D lagune@{{version}}
```

:::

**Lagune** adapts to your environment, whether it is a new project or an existing one.

:::info[No keys]
No API keys are needed, it runs directly through your own agent ([**Claude**, **Codex**, and more](/docs/supported-agents)).
:::

<Tabs>
  <TabItem value="prompt" label="CLI" default>

Install **Lagune**'s commands with the [**skills** CLI](https://github.com/vercel-labs/skills). It detects the agents in your project, or asks which ones to set up:

```bash
npx skills add wellwelwel/lagune
```

The commands land in the project by default. To install them once for every project, add `--global`:

```bash
npx skills add wellwelwel/lagune --global
```

:::info[Any language]
🃏 **Lagune** runs on **Node.js** under the hood, you use whatever language you want.
:::

## What gets created

**Lagune** keeps three things apart, so nothing is generated into your project:

- **Your project's state** lives in `.lagune/`: the charter, the artifact each phase produces, the internal tracking, and the project's catalog (the categories it uses and its own specializations). The first command that writes creates it, and it is committed alongside your code, versioned and reviewable like any other part of the project.
- **Lagune's commands** are the nine skills the **skills** CLI installs where your agent reads them, so the `/lagune.*` commands are ready to run.
- **Lagune's engine** is the `lagune` package on **npm**. The commands run it through `npx` for every deterministic step, at the exact version they carry. The first call downloads it once, and later calls stay off the network. To run with no network at all, see [**Offline**](/docs/get-started/offline).

## Update

To update **Lagune**'s commands to their latest version, run:

```bash
npx skills update
```

The engine version the commands call moves with them.

:::tip
Your charter, the artifacts each phase produces, the internal tracking, and every specialization you authored with [`/lagune.specialize`](/docs/commands/specialize) stay untouched.
:::

## Specializations

**Lagune** ships focused security [**specializations**](/docs/commands/catalog) grouped into [**categories**](/docs/categories), from `owasp` to per-language ones like `python`, `go`, and `rust`. The categories a project uses decide which built-in specializations join its catalog, and `.lagune/catalog.json` records them, so the whole team works with the same set.

While no category is recorded, the project uses `owasp` alone. [`/lagune.charter`](/docs/commands/charter) then records each category its reading of the project supports, such as its language, calls to an LLM, or containers, and never changes them once recorded. You can change them yourself anytime.

### Add and remove anytime

`--categories` with no value opens an interactive picker in a terminal (space to toggle, enter to confirm, empty to skip). Outside a terminal, pass the categories after it.

<Tabs>
  <TabItem value="add" label="Add" default>

```bash
npx --yes lagune@latest add --categories # interactive
npx --yes lagune@latest add --categories owasp
npx --yes lagune@latest add --categories owasp rust
```

  </TabItem>
  <TabItem value="remove" label="Remove">

```bash
npx --yes lagune@latest remove --categories # interactive
npx --yes lagune@latest remove --categories owasp
npx --yes lagune@latest remove --categories owasp rust
```

  </TabItem>
</Tabs>

The first `add` or `remove` starts from `owasp`, so removing every category leaves an empty list, never the default.

### See what exists

`list` on its own asks what you want to see, the findings **Lagune** is tracking or the specialization categories, then prints that. Skip the prompt with a flag: `--findings` for the tracked findings, `--categories` for the categories.

```bash
npx --yes lagune@latest list --categories
# Categories
#   • owasp       [used]       Harden against the application security risks OWASP tracks
#   • javascript  [available]  Harden JavaScript and its runtimes
#   • php         [available]  Harden PHP against type-juggling auth bypass
#   • go          [available]  Harden Go against typed-nil interface bugs
#   ...
#
# No category is recorded yet, so this project uses the default: owasp.
```

`catalog` prints the specializations the project uses, built-in and its own, one per line:

```bash
npx --yes lagune@latest catalog
# regex: Regular Expression [required]
# network: Requests, Webhook, URL Fetch, Socket, IMDS, Redirect
# ...
```

See every category in [**Categories**](/docs/categories).

  </TabItem>

Run **Lagune** directly with no subcommand for an interactive live view of `.lagune/`. It serves a dashboard and opens it on a random port:

```bash
npx --yes lagune@latest
```

- [x] **Live Reload**
- [x] **Private** and **Local**
- [x] Shows whatever `.lagune/` holds, from the first charter on
- [x] **Manage** the project's categories directly from your browser
- [x] No `node_modules` or `package.json` is needed 📦

## Requirements

You will need these tools installed on your system:

- [**Node.js (LTS)**](https://nodejs.org/en/download/package-manager)
- An agent the **skills** CLI supports, see [**Supported Agents**](/docs/supported-agents)

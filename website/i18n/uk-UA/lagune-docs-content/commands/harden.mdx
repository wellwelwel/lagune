# /lagune-harden

🔧 Застосуйте виправлення з плану до свого коду, безпечно й по одному.

## Використання

<Tabs>
  <TabItem value="full" label="Застосувати все" default>

```prompt
/lagune-harden
```

  </TabItem>
  <TabItem value="paths" label="Вказати шляхи">

```prompt
/lagune-harden src/routes/upload.ts
```

  </TabItem>
  <TabItem value="priority" label="За пріоритетом">

```prompt
/lagune-harden Critical і High
```

  </TabItem>
</Tabs>

## Як це працює

План уже визначив кожне виправлення, тож harden просто застосовує його. Оскільки це єдина фаза, що торкається вашого коду, вона діє обережно: застосовує по одному виправленню, щоб кожну зміну було легко переглянути, і ніколи не послаблює засіб захисту, щоб припасувати виправлення. Наприклад, виправлення для завантаження:

- **Завантаження файлів** (Статус: **Applied**)
  - _Що змінилося:_ перевіряє справжній тип і розмір файлу, відхиляє все неочікуване, перейменовує файл під час збереження й зберігає його там, де його неможливо виконати як код.
  - _Де:_ функція `handleUpload`, а також допоміжна функція сховища, яку вона викликає.

Якщо виправлення неможливо застосувати повністю, harden робить те, що може безпечно, а решту позначає як **Partial** або **Blocked**, залишаючи її відкритою.

:::info[Applied не означає перевірене]
Applied ще не означає доведене. Для цього існує [verify](/docs/commands/verify).
:::

:::tip

- Фаза повністю спирається на план. Якщо виправлення чи файл ще не сплановано, вона попросить спершу виконати для нього `/lagune-plan`.
- Повторний запуск узгоджує журнал: скасовані зміни зникають, нові застосовані виправлення з'являються.
- Журнал посилення захисту зберігається в `.lagune/memory/harden.md`.

:::

:::warning[Залежить від plan і змінює ваш код]
Harden спирається на [`/lagune-plan`](/docs/commands/plan). Це єдина фаза, що змінює ваш код.
:::

## Далі

Доведіть, що кожне виправлення діє: [`/lagune-verify`](/docs/commands/verify).

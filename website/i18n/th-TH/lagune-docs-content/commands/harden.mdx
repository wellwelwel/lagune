# /lagune-harden

🔧 นำการแก้ไขจากแผนไปใช้กับโค้ดของคุณอย่างปลอดภัย ทีละรายการ

## หลักการทำงาน

plan ตัดสินการแก้ไขแต่ละรายการไว้แล้ว harden จึงแค่นำไปใช้ เฟสนี้เป็นเฟสเดียวที่แตะโค้ดของคุณ จึงทำงานอย่างระมัดระวัง: นำการแก้ไขไปใช้ทีละรายการเพื่อให้ตรวจทานการเปลี่ยนแปลงแต่ละครั้งได้ง่าย และไม่ลดทอนมาตรการควบคุมเพื่อให้การแก้ไขลงตัว ตัวอย่างเช่น การแก้ไขเรื่องการอัปโหลด:

- **การอัปโหลดไฟล์** (สถานะ: **Applied**)
  - _สิ่งที่เปลี่ยน:_ ตรวจชนิดจริงและขนาดของไฟล์ ปฏิเสธทุกอย่างที่ไม่ได้คาดไว้ เปลี่ยนชื่อไฟล์ตอนบันทึก และเก็บไว้ในที่ที่รันเป็นโค้ดไม่ได้
  - _ตำแหน่ง:_ ฟังก์ชัน `handleUpload` และ helper สำหรับจัดเก็บที่ฟังก์ชันนี้เรียกใช้

ถ้านำการแก้ไขไปใช้ได้ไม่ครบ harden จะทำส่วนที่ทำได้อย่างปลอดภัย แล้วทำเครื่องหมายส่วนที่เหลือเป็น **Partial** หรือ **Blocked** โดยเปิดค้างไว้

:::info[นำไปใช้แล้วยังไม่เท่ากับผ่านการพิสูจน์]
Applied ยังไม่ได้แปลว่าพิสูจน์แล้ว นั่นคือหน้าที่ของ [verify](/docs/commands/verify)
:::

:::tip

- คำสั่งนี้สร้างต่อจากแผนทั้งหมด ถ้าการแก้ไขหรือไฟล์ใดยังไม่เคยอยู่ในแผน คำสั่งนี้จะบอกให้คุณรัน `/lagune-plan` กับสิ่งนั้นก่อน
- รันซ้ำเพื่อปรับบันทึกให้ตรงกับสภาพปัจจุบัน: การเปลี่ยนแปลงที่ถูกย้อนกลับจะหายไป และการแก้ไขที่เพิ่งนำไปใช้จะเข้ามา
- บันทึก hardening อยู่ที่ `.lagune/memory/harden.md`

:::

:::warning[ต้องรัน plan ก่อน และจะแก้ไขโค้ดของคุณ]
harden สร้างต่อจาก [`/lagune-plan`](/docs/commands/plan) และเป็นเฟสเดียวที่แก้ไขโค้ดของคุณ
:::

# /lagune-harden

🔧 Примените исправления из плана к своему коду, безопасно и по одному.

## Использование

<Tabs>
  <TabItem value="full" label="Применить все" default>

```prompt
/lagune-harden
```

  </TabItem>
  <TabItem value="paths" label="Указать пути">

```prompt
/lagune-harden src/routes/upload.ts
```

  </TabItem>
  <TabItem value="priority" label="По приоритету">

```prompt
/lagune-harden критический и высокий приоритет
```

  </TabItem>
</Tabs>

## Как это работает

План уже определил каждое исправление, поэтому harden просто применяет его. Это единственная фаза, которая трогает ваш код, поэтому она действует осторожно: применяет исправления по одному, чтобы каждое изменение было легко проверить, и никогда не ослабляет меру защиты, чтобы исправление подошло. Например, исправление загрузки:

- **Загрузка файлов** (статус: **Applied**)
  - _Что изменилось:_ проверяет настоящий тип и размер файла, отклоняет все неожиданное, переименовывает файл при сохранении и хранит его там, где его нельзя выполнить как код.
  - _Где:_ функция `handleUpload` и вспомогательная функция хранилища, которую она вызывает.

Если исправление нельзя применить полностью, harden делает то, что может сделать безопасно, а остальное помечает как **Partial** или **Blocked**, оставляя его открытым.

:::info[Применено не значит проверено]
Applied еще не означает, что исправление доказано. Для этого нужна [verify](/docs/commands/verify).
:::

:::tip

- Фаза целиком опирается на план. Если исправление или файл так и не попали в план, она попросит сначала запустить для них `/lagune-plan`.
- Повторный запуск сверяет журнал: отмененные изменения уходят, новые примененные исправления появляются.
- Журнал усиления защиты хранится в `.lagune/memory/harden.md`.

:::

:::warning[Зависит от plan и меняет ваш код]
Harden опирается на [`/lagune-plan`](/docs/commands/plan). Это единственная фаза, которая меняет ваш код.
:::

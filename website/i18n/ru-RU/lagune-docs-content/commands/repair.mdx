# /lagune-repair

🧰 Восстановите цепочку, когда ее сбивает переименование или перемещение файла.

:::note[Внутреннее обслуживание, а не фаза безопасности]
Repair не является шестой фазой линейного процесса. Ее задача: поддерживать согласованность отслеживания.
:::

```prompt
# Входных данных не нужно: команда всегда восстанавливает всю цепочку
/lagune-repair
```

## Как это работает

Каждая находка detect представляет собой один отслеживаемый элемент, который переносят дальше plan, harden и verify: каждая фаза работает с ним и снова сообщает о нем по имени. Это имя, записанное одинаково как заголовок раздела в каждом артефакте, служит его идентификатором на всем пути.

Единственное изменчивое, что хранит отслеживание, это пути к файлам, на которые указывает элемент. Эти пути больше нигде не хранятся, поэтому переименование или перемещение файла может сломать связь только там, а не в двух расходящихся копиях. Когда это случается, repair исправляет карту (`.lagune/tracking.json`), чтобы идентификатор пережил переименование. Команда читает артефакты и карту отслеживания, читает ваш исходный код только для того, чтобы узнать новый путь переименованного файла, и никогда не пишет содержимое о безопасности.

За тот же проход она сверяет каждый артефакт памяти с его шаблоном и сообщает, что отклонилось, указывая для каждого расхождения фазу, которая его исправляет.

:::tip

- Она не трогает ни ваш код, ни текстовые артефакты, только отслеживание.
- Запускать ее вручную приходится редко. Когда фаза замечает, что цепочка несогласованна, она сама запускает repair и продолжает работу.
- Отслеживание, которое она поддерживает, хранится в `.lagune/tracking.json`, во внутреннем состоянии, которое вы никогда не правите вручную.

:::

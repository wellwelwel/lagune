🔀 マニフェスト方式の **Lagune** プロジェクトを、書いた内容をすべて保ったまま、スキル方式の **Lagune** に移行します。

:::danger[非推奨のお知らせ]

マニフェストを持つプロジェクトは、`v1.x` までは今のまま動作します。`npx lagune` が `init`、`pull`、`update`、`add`、`remove`、`list`、ダッシュボードを、マニフェスト方式の最後のバージョンである `lagune@0.15.0` に引き渡すからです。

:::

## 移行手順

1. 現在の作業がコミット済みであることを確認してから、プロジェクトのルートで migrate を実行します：

   ```bash
   npx lagune migrate
   ```

2. migrate による変更を単独でコミットし、移行をレビューしやすい 1 つの変更にまとめます。
3. [インストールページ](/docs) の手順に従って、使っているエージェント向けにコマンドをインストールします。
4. プロジェクトにすでに detect、plan、harden のいずれかの成果物がある場合は、それらの成果物と独自の専門知識に残っている古い参照を照合して更新するよう、[`/lagune-repair`](/docs/commands/repair) に依頼します：

   ```prompt
   /lagune-repair `.lagune/memory/` 配下の成果物（`detect.md`、`plan.md`、`harden.md`）に記載されている適用済みの専門知識（旧称 sub-skills）を、新しいカタログに載っている名前と照合して更新してください。また、`.lagune/catalog/` にある自分の専門知識が `.lagune/hooks/` の古いフックを呼び出している箇所を、すべて `lagune_read` または `lagune_write` ツールの呼び出しに書き換えてください。
   ```

## 変更点

| 移行前                                                               | 移行後                                                                                         |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `.lagune/templates/`、`.lagune/hooks/`、`.lagune/specializations.md` | 削除：テンプレートは各スキルが持ち、フックはエンジンが実行する                                 |
| `.lagune/skills/` にある組み込みの専門知識のコピー                   | 削除：組み込みの専門知識はエンジンが提供する                                                   |
| `.lagune/skills/` にある独自の専門知識                               | `.lagune/catalog/` に移動                                                                      |
| `.lagune/skills.json`（独自の専門知識のインデックス）                | `.lagune/configs.json` に統合                                                                  |
| マニフェストのカテゴリ                                               | `.lagune/configs.json` に記録                                                                  |
| 旧エージェントコマンド（`/lagune.detect` など）                      | 削除：[**Lagune** をインストール](/docs) すると、新しいコマンド（`/lagune-detect` など）が入る |
| `.gitignore` 内の **Lagune** ブロック                                | 削除（ほかに何も書かれていなければ、ファイルごと削除）                                         |
| `.lagune/proofs/`（そのブロックで除外されていたもの）                | 専用の `.gitignore` でコミットの対象外になる                                                   |
| `.lagune/manifest.json`                                              | 最後に削除                                                                                     |

セキュリティの作業（セキュリティ原則、各フェーズが生成した成果物、各検出事項が指すパスを保持する追跡マップ）は、そのまま残ります。

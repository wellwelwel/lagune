Referanser og kilder

OWASP-kilder

Hvor kunnskapen i de innebygde OWASP-spesialiseringene kommer fra, koblet til de kanoniske OWASP-sidene om angrep og Cheat Sheets.

Dette dokumentet knytter hvert angrep (www-community) og hvert Cheat Sheet (CheatSheetSeries) fra OWASP til en sikkerhetskategori, hver med lenke til den kanoniske offentlige siden. Innenfor en kategori deler likeverdige oppføringer én linje i sjekklisten: Angrepene og Cheat Sheets som håndterer den samme risikoen, står sammen, skilt med komma. Oppføringer uten en direkte motpart står på en egen linje.

  • Æren tilhører OWASP. Angrepene ligger på https://owasp.org/www-community/attacks/<attack>, og Cheat Sheets på https://cheatsheetseries.owasp.org/cheatsheets/<cheat>.html.

31. Sky, containere og infrastruktur​

Konfigurasjon av containere og arbeidslaster er konfigurasjon som kode som utvikleren leverer sammen med appen (Dockerfile, Compose, securityContext for Pod), en reell flate som harden utbedrer og verify beviser, så den er innenfor omfanget. Klyngeadministrasjon (RBAC, etcd, API-server, admission, nettverkssegmentering) er driftsansvarliges domene og holdes utenfor omfanget.

  • Docker Security, Node.js Docker (container)
  • Kubernetes Security (container: delen om arbeidslaster og Pods. Klyngeadministrasjon holdes utenfor omfanget)
  • Serverless / FaaS Security (serverless)

  • NPM Security (interpreter)

33. Hemmeligheter og konfigurasjon​

Håndtering av hemmeligheter er en driftsoppgave: hvelv, CI/CD, skykonfigurasjon, rotasjon. Den ene siden som gjelder koden (en hemmelighet hardkodet i kildekoden), dekkes av en deterministisk gjennomgang, ikke av en risikospesialisering. Flyttet til "Utenfor omfanget".

34. Prosess, design og styring​

Personvern for brukere handler om retningslinjer og design (dataminimering, åpenhet, oppbevaring), ikke om en flate i koden som en spesialisering forsvarer. Flyttet til "Utenfor omfanget".

35. Betalinger og etterlevelse​

  • Secure Integration of Third-Party Payment Gateways (payment)

36. Innebygde systemer, IoT og spesialiserte domener​

Sikkerhet for kjøretøy og droner hører til domenet for innebygde systemer (CAN-buss, OTA-fastvare, integritet for sensorer og radio, fysisk tilgang), ikke til kildekoden for web- og API-applikasjoner som Lagune reviderer. Flyttet til "Utenfor omfanget".

Utenfor omfanget (ingen flate i koden)​

Dette er ikke områder for spesialiseringer og har ingen avkrysningsboks: Det dreier seg om styring, prosess, herding av driften eller bruk av rammeverk, uten en enkelt flate i koden som en spesialisering per flate kan forsvare. Sikkerhetsverdien er reell, men den ligger i prosess og arkitektur (eller, for et rammeverk, i den egne skillen for det språket), ikke i et forsvar denne katalogen leverer. De står her som referanse, ikke som arbeid som gjenstår.

  • Authorization Regression Testing, Authorization Testing Automation
  • JAAS
  • Denial of Service, Denial of Service
  • HTTP/2 Reset Attack
  • Traffic flood
  • Web Service Amplification Attack (forsterkning via SOAP/WS-Addressing, en driftsmessig DoS-variant uten flate i koden)
  • Cash Overflow
  • Spyware, Trojan Horse (skadevare hos sluttbrukeren, ikke en flate i koden til prosjektet som revideres. Leveransen i nettleseren hører til browser)
  • REST Security, REST Assessment
  • Web Service Security
  • Cloud Architecture Security (design og avveininger: IAM kontra signerte URL-er, offentlige og private VPC-er, tillitsgrenser, delt ansvar. I motsetning til container har den ingen konkret konfigurasjon som en spesialisering sjekker)
  • Infrastructure as Code Security (til tross for navnet handler det om SDLC-prosess og verktøy for å forvalte IaC: IDE-plugins, statisk analyse, skanning av images, CI/CD, signering. Den viser ingen vei fra et usikkert mønster til en trygg form i en Terraform- eller CloudFormation-fil)
  • Kubernetes Security (bare delen om klyngeadministrasjon: RBAC, etcd, API-server, admission. Delen om arbeidslaster og Pods er innenfor omfanget under container)
  • Network Segmentation (nettverksarkitektur og brannmurregler)
  • Subdomain Takeover Prevention (livssyklus og overvåking av DNS, ikke kode)
  • Secrets Management (hvelv, CI/CD, rotasjon. Hardkodede hemmeligheter dekkes av en deterministisk gjennomgang, ikke av en risikospesialisering)
  • C-Based Toolchain Hardening (flagg for kompilator, linker og bygging, uten sink i kildekoden)
  • Microservices Security, Microservices based Security Arch Doc
  • Zero Trust Architecture
  • CI/CD Security, GitHub Actions Security
  • Software Supply Chain Security
  • Error Handling, Full Path Disclosure (global konfigurasjon av feilhåndtering per stakk. Lekkasjen er den samme avsløringen som feilhåndteringen allerede styrer)
  • Abuse of Functionality, Business Logic Security, Abuse Case (historisk) (applikasjonsspesifikt design, ingen enkelt sink i koden)
  • User Privacy Protection (dataminimering, åpenhet, regler for oppbevaring)
  • Top 10 Automotive Security Vulnerabilities, Drone Security (domener for innebygde systemer: CAN-buss, OTA-fastvare, integritet for sensorer og radio, ikke kildekode for web og API)
  • Mobile Application Security (herding av plattformene Android og iOS: lagring, biometri, pinning, personopplysninger. Den har ingen enkelt flate i koden, og innlasting av ikke-klarert kode ble flyttet til interpreter)
  • Threat Modeling, Threat Modeling (fellesskapsside)
  • Attack Surface Analysis
  • Secure Product Design
  • Secure Code Review
  • Virtual Patching
  • Vulnerability Disclosure
  • Legacy Application Management
  • Security Terminology

Lagune и Deepsec: два подхода к безопасности на основе ИИ бок о бок

Справочное сравнение Lagune и Deepsec от Vercel по принципу работы, жизненному циклу, обнаружению, стоимости, находкам и закрытию.

Lagune и Deepsec (v2.2.1) представляют собой два защитных ответа на одну и ту же проблему: безопасность в эпоху разработки с помощью ИИ. Их исходная посылка, их начало, середина и конец, а также то, как каждый из них предстает перед пользователем, расходятся намеренно, даже там, где их механизмы пересекаются.

подсказка

Вдохновлен ли Lagune проектом Deepsec? Нет, Lagune написан с нуля и вдохновлен Spec-Driven Development и Security Hardening. Два проекта разрабатывались независимо, а это сравнение призвано помочь пользователям понять их различия.

Как это работает​

Lagune ставит агента на первое место: агент ведет работу, подключает знания по запросу под то, чем является код, и делегирует однозначно решаемую часть детерминированным хукам.

Deepsec ставит на первое место детерминированность: широкое сканирование помечает кандидатов, которые указывают обязательной модели, что расследовать и оценивать.

АспектLaguneDeepsec
ПорядокПринципы безопасности и подобранные знания направляют агента, который делегирует хукам и оценивает остальноеСопоставители помечают кандидатов, модель расследует и оценивает каждого
Роль детерминированностиМногоязычные хуки, которые выносят вердикт или нацеливают агента, в сочетании со знаниями категорийСопоставители, которые помечают кандидатов для оценки обязательной моделью
Процесс разработки/lagune создает безопасный код прямо по ходу программированияОн проверяет код, но не пишет его
Процесс аудитаcharter → detect → plan → harden → verifyscan → process → triage → revalidate → report
Задача ИИРассуждать на основе знаний, применить исправление и доказать, что оно действуетРасследовать каждого кандидата и сообщить о находках

Жизненный цикл​

Lagune работает до, во время и после написания кода. Deepsec проверяет репозиторий, когда код уже существует.

МоментLaguneDeepsec
До появления кодаcharter выводит политику безопасности из заявленного намеренияНачинает с существующего кода: init нужна директория
Во время разработки/lagune создает код, безопасный по умолчанию, прямо по ходу, не оставляя артефактовПроверяет после разработки, а не во время нее
Для существующего кодаdetect → plan → harden → verifyscan → process, основной процесс
Непрерывная проверкаПовторный запуск фаз для нужного охвата, без готового шлюза для CIИнкрементальное повторное сканирование, process --diff как шлюз выхода в CI

Знания и суждение​

Оба несут знания о безопасности, недоступные регулярным выражениям. Различаются они тем, где эти знания живут и кто может их формировать.

АспектLaguneDeepsec
ФормаРедактируемые модули на markdown, некоторые из которых опираются на детерминированный хукКороткий промпт и подсказки по технологиям, опирающиеся на собственные знания модели
ВыборПодбираются под код и загружаются, только когда присутствует их контекстВнедряется в каждый пакет для ИИ, плюс подсказки для обнаруженных технологий
Кто их пишетПользователь правит модули и добавляет новые с помощью specializeПромпт принадлежит мейнтейнеру, а пользователь заполняет INFO.md
Где находится суждениеХуки решают свой минимум, а остальное агент оценивает на основе знанийЦентрализованно: один обработчик ИИ оценивает каждого кандидата
Повторное использованиеОдин модуль направляет и detect, и verifyОдин промпт управляет единственным этапом process

Пользовательский опыт​

Как каждый встречает того, кто его запускает: что нужно для первого запуска и как оператор его направляет.

Первый запуск​

Lagune работает через уже открытого агента. Deepsec сначала разворачивает собственное рабочее пространство и доступ к модели.

АспектLaguneDeepsec
Первая командаУстановка плагина или npx skills add wellwelwel/lagune -y, затем /lagune-* в агентеnpx deepsec init, затем cd .deepsec, pnpm install, scan, process
Учетные данные для запускаОтдельный ключ не нужен, используется ваш текущий агентКлюч модели (например, AI Gateway, 12-часовой токен Vercel OIDC или токен Anthropic)

Управление​

Оба принимают указания. Lagune читает форму входных данных для каждой фазы. Deepsec сужает набор файлов, по которому идет то же самое расследование.

АспектLaguneDeepsec
Весь проектФаза без входных данных сканирует весь охватscan и process проходят репозиторий
Часть проектаЛюбую фазу можно ограничить заданными файлами или директориями--files, --files-from или --diff сужают запуск
ОпасениеФазу можно ограничить описанным опасениемПромпт расследования фиксирован
Диапазон приоритетаharden и verify можно ограничить уровнями Critical, High, Medium или LowНаходки получают метки после запуска
Отдельное значениеХук напрямую оценивает один фрагмент, шаблон или URL (--pattern, --url)Единица работы: файл

Частые вопросы

Lagune ставит агента на первое место и работает до, во время и после написания кода: задает политику до появления кода, усиливает защиту прямо во время разработки и проводит аудит, исправляет и проверяет уже написанный код. Deepsec ставит на первое место детерминированность: широкое сканирование регулярными выражениями питает обязательное расследование моделью уровня frontier, которое проверяет существующий код и сообщает о находках, не меняя его.

Весь процесс Lagune может работать за $0 на бесплатной локальной модели, а его детерминированные хуки выносят вердикты вообще без ИИ. Сканирование Deepsec бесплатно, но не выносит вердиктов, поэтому для любой находки нужен его платный этап ИИ.

Lagune меняет: harden применяет исправления к вашему коду. Deepsec не меняет: это только статический анализ, который выдает находки и текст рекомендаций, а применяет их отдельно человек или агент.

Referensi dan sumber

Sumber OWASP

Asal pengetahuan spesialisasi OWASP bawaan, dipetakan ke halaman serangan dan Cheat Sheet OWASP yang kanonis.

Dokumen ini memetakan setiap serangan (www-community) dan Cheat Sheet (CheatSheetSeries) OWASP ke sebuah kategori keamanan, masing-masing dengan tautan ke halaman publik kanonisnya. Dalam satu kategori, item yang setara berbagi satu baris daftar periksa: serangan dan cheat sheet yang menangani risiko yang sama dicantumkan bersama, dipisahkan koma. Item tanpa padanan langsung berdiri di barisnya sendiri.

  • Kredit sepenuhnya milik OWASP. Serangan ada di https://owasp.org/www-community/attacks/<attack> dan cheat sheet di https://cheatsheetseries.owasp.org/cheatsheets/<cheat>.html.

31. Cloud, container, dan infrastruktur​

Konfigurasi container dan workload adalah config-as-code yang dikirim developer bersama aplikasinya (Dockerfile, Compose, securityContext milik Pod), permukaan nyata yang diperbaiki oleh harden dan dibuktikan oleh verify, jadi masuk dalam cakupan. Administrasi cluster (RBAC, etcd, API server, admission, segmentasi jaringan) adalah ranah operator dan tetap di luar cakupan.

  • Docker Security, Node.js Docker (container)
  • Kubernetes Security (container: bagian workload dan Pod. Administrasi cluster tetap di luar cakupan)
  • Serverless / FaaS Security (serverless)

32. Rantai pasok dan CI/CD​

  • NPM Security (interpreter)

33. Secret dan konfigurasi​

Manajemen secret bersifat operasional: vault, CI/CD, konfigurasi cloud, rotasi. Satu-satunya sisi di level kode (secret yang hardcoded di kode sumber) adalah pemindaian deterministik, bukan spesialisasi risiko. Dipindahkan ke "Di luar cakupan".

34. Proses, desain, dan tata kelola​

Perlindungan privasi pengguna adalah urusan kebijakan dan desain (minimalisasi data, transparansi, retensi), bukan permukaan kode yang dipertahankan sebuah spesialisasi. Dipindahkan ke "Di luar cakupan".

35. Pembayaran dan kepatuhan​

  • Secure Integration of Third-Party Payment Gateways (payment)

36. Sistem embedded, IoT, dan domain khusus​

Keamanan otomotif dan drone adalah domain sistem embedded (CAN bus, firmware OTA, integritas sensor dan radio, akses fisik), bukan kode sumber aplikasi web atau API yang diaudit Lagune. Dipindahkan ke "Di luar cakupan".

Di luar cakupan (tanpa permukaan kode)​

Item berikut bukan wilayah spesialisasi dan tidak punya kotak centang: semuanya berupa tata kelola, proses, hardening operasional, atau penggunaan framework, tanpa satu permukaan kode yang bisa dipertahankan oleh spesialisasi per permukaan. Nilai keamanannya nyata, tetapi letaknya di proses dan arsitektur (atau, untuk framework, di skill bahasa itu sendiri), bukan di pertahanan yang dibawa katalog ini. Dicantumkan sebagai referensi, bukan sebagai pekerjaan.

  • Authorization Regression Testing, Authorization Testing Automation
  • JAAS
  • Denial of Service, Denial of Service
  • HTTP/2 Reset Attack
  • Traffic flood
  • Web Service Amplification Attack (amplifikasi SOAP dan WS-Addressing, varian DoS operasional tanpa permukaan kode)
  • Cash Overflow
  • Spyware, Trojan Horse (malware di sisi pengguna akhir, bukan permukaan kode di proyek yang diaudit. Sisi penyebarannya lewat browser ada di browser)
  • REST Security, REST Assessment
  • Web Service Security
  • Cloud Architecture Security (desain dan trade-off: IAM versus signed URL, VPC publik dan privat, batas kepercayaan, tanggung jawab bersama. Berbeda dengan container, tidak ada konfigurasi konkret yang bisa diperiksa sebuah spesialisasi)
  • Infrastructure as Code Security (meski namanya begitu, isinya adalah proses SDLC dan tooling untuk mengelola IaC: plugin IDE, analisis statis, pemindaian image, CI/CD, penandatanganan. Tidak ada pola tidak aman yang diubah ke bentuk aman di dalam file Terraform atau CloudFormation)
  • Kubernetes Security (hanya bagian administrasi cluster: RBAC, etcd, API server, admission. Bagian workload dan Pod masuk cakupan di bawah container)
  • Network Segmentation (arsitektur jaringan dan kebijakan firewall)
  • Subdomain Takeover Prevention (siklus hidup dan pemantauan DNS, bukan kode)
  • Secrets Management (vault, CI/CD, rotasi. Sisi secret yang hardcoded adalah pemindaian deterministik, bukan spesialisasi risiko)
  • C-Based Toolchain Hardening (flag compiler, linker, dan build, tanpa sink di kode sumber)
  • Microservices Security, Microservices based Security Arch Doc
  • Zero Trust Architecture
  • CI/CD Security, GitHub Actions Security
  • Software Supply Chain Security
  • Error Handling, Full Path Disclosure (konfigurasi error handler global per stack. Kebocorannya adalah pengungkapan yang sama yang sudah diatur oleh penanganan error)
  • Abuse of Functionality, Business Logic Security, Abuse Case (historical) (desain yang spesifik untuk tiap aplikasi, tanpa satu sink di kode)
  • User Privacy Protection (minimalisasi data, transparansi, kebijakan retensi)
  • Top 10 Automotive Security Vulnerabilities, Drone Security (domain sistem embedded: CAN bus, firmware OTA, integritas sensor dan radio, bukan kode sumber web atau API)
  • Mobile Application Security (hardening platform Android dan iOS: penyimpanan, biometrik, pinning, PII. Tidak punya satu permukaan kode, dan sisi pemuatan kode tidak tepercaya dipindahkan ke interpreter)
  • Threat Modeling, Threat Modeling (community page)
  • Attack Surface Analysis
  • Secure Product Design
  • Secure Code Review
  • Virtual Patching
  • Vulnerability Disclosure
  • Legacy Application Management
  • Security Terminology

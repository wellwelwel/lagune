# Contributing

If you're thinking of contributing, thank you, and _naturally_, please **be respectful** 🙋🏻‍♂️

## AI & Open Source

🤖 **LLM**s can help a lot with productivity, but please, use them as a tool, not as an autopilot.

**Lagune** exists because software increasingly ships without anyone recognizing an insecure pattern. A contribution nobody read is that same problem arriving from the other side, so every change here is expected to have been reviewed by a human, from end to end.

Please avoid lengthy texts generated by **LLM**s.

- If it's an issue, focus on the error description, how to reproduce it, and what the expected behavior should be.
- If it's a pull request, make sure the description links to the issue it resolves and briefly describe what has changed and why.

You can use **LLM**s to review, correct, or improve your grammar with ease. We'll love reading what you, **a human**, have written 🤝

> [!IMPORTANT]
>
> Pull Requests that do not respect the rules above may be closed automatically by **GitHub** bot.

## Issues

By opening an **Issue**, please describe the problem.<br />
If you can share a basic repro, it will be great.

---

## Pull Requests

By opening a **Pull Request**, please describe the proposed solution and what it solves.<br />
The final commit message will be generated from the _PR_ title by using "**Squash and Merge**".

- Please keep each _PR_ focused on a single responsibility. If your change mixes unrelated things, split it into separate _PRs_, since smaller and focused ones are easier to review and keep the versioning clean.
- Also be careful when changing existing tests. It usually means a breaking change or that something that used to work no longer does, so prefer adding new tests and only change an existing one when there's really no other way _(an intentional breaking change, a test that was genuinely wrong, etc.)_.

## Developing

### ⚙️ Environment

You will need [**Node.js (LTS)**](https://nodejs.org/en/download/package-manager) installed on your system.

---

Fork this project, download your forked repository locally and create a new branch from `main`.<br />
Then run `npm ci` to clean install the _node_modules_:

```sh
npm ci
```

> Please, do not change the _package-lock.json_ manually.

---

### 🌊 What you are changing

**Lagune** is two layers, and knowing which one you are in saves most of the guesswork.

- **`skills/`** and **`catalog/`** carry the security value: the nine commands the [**skills.sh**](https://www.skills.sh/wellwelwel/lagune) or an agent's own plugin installer installs, each beside the template it fills, and the built-in specializations they load on demand. They are agent-agnostic and written once.
- **`src/`** carries the engine the commands call: the deterministic hooks, the catalog, validation, the move from a **Lagune** CLI install, and the dashboard.

### 🔧 Fixes

Where possible, provide a test case that the fix covers.

### ❇️ Features

It's better to discuss a feature before actually starting to implement it. You can open an [**Issue on GitHub**](https://github.com/wellwelwel/lagune/issues/new), so we can discuss the design ideas.

> Please ensure test cases to cover new features.

> [!TIP]
>
> - [ ] Does it belong in a command's text, a specialization, or the engine?
> - [ ] Is it defensive? **Lagune** hardens and verifies, and never ships offensive tooling or exploits for malicious use.
> - [ ] Are the tests simulating real user usage?

---

### 🧠 Design Preferences (Architecture)

- **TypeScript in, JavaScript out.** Author in `src/`, and let the build produce `lib/`. Never edit `lib/` by hand.
- **Every type declaration lives in `src/types/`.** Nothing declares a `type` or an `interface` anywhere else.
- **`any` and `as unknown as` are forbidden.** Reach for `as` last, preferring a direct annotation or `satisfies`.
- **Named exports only**, arrow functions declared with `const`, early returns over nesting, and no abbreviated names.
- **Prefer native capabilities over external dependencies.** The published bundle is self-contained, so the engine command needs no install on the user's machine.
- **Adding a built-in specialization is one file in `catalog/` plus one row in the built-in index**, never a new command.
- **A command only calls what the published engine supports.** Every engine call carries the package version, which the release pull request moves, and most agents install `skills/` from the default branch as it stands, so a change that needs new engine behavior lands together with the release that publishes it.
- **Prefer the async Node.js APIs**, and always prefix native imports with `node:`.

> [!NOTE]
>
> Please do not add runtime dependencies to the project.
>
> - Development dependencies can be discussed.

#### ✌🏻 Tips

- You can open a Pull Request in your own fork to run the entire test suite without having to install anything on your computer.
  - Just remember to enable the workflows in the Actions tab of your fork.
  - When you're done, you can open your Pull Request in the **Lagune** repository to share your changes with the entire community.

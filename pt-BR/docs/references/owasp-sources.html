Fontes da OWASP

De onde vem o conhecimento das especializações nativas da categoria OWASP, mapeado para as páginas canônicas de ataques e Cheat Sheets da OWASP.

Este documento mapeia cada ataque (www-community) e cada Cheat Sheet (CheatSheetSeries) da OWASP para uma categoria de segurança, cada um com o link para a página pública canônica dele. Dentro de uma categoria, itens equivalentes dividem uma única linha da lista: os ataques e as cheat sheets que tratam do mesmo risco aparecem juntos, separados por vírgula. Itens sem uma contrapartida direta ficam em uma linha própria.

  • O crédito é da OWASP. Os ataques ficam em https://owasp.org/www-community/attacks/<attack> e as cheat sheets em https://cheatsheetseries.owasp.org/cheatsheets/<cheat>.html.

25. Lógica de negócio e abuso de funcionalidade​

Lógica de negócio e abuso de funcionalidade não têm uma superfície única no código que uma especialização por superfície defenda: a defesa é um design específico da aplicação, o mesmo raciocínio que conduz a modelagem de ameaças do projeto. Movido para "Fora do escopo".

31. Nuvem, contêineres e infraestrutura​

A configuração de contêineres e workloads é configuração como código que quem desenvolve entrega junto com o app (Dockerfile, Compose, securityContext do Pod), uma superfície real que o harden corrige e o verify comprova, então ela está no escopo. A administração do cluster (RBAC, etcd, API server, admission, segmentação de rede) é domínio de quem opera a infraestrutura e fica fora do escopo.

  • Docker Security, Node.js Docker (container)
  • Kubernetes Security (container: a parte de workloads e Pods. A administração do cluster fica fora do escopo)
  • Serverless / FaaS Security (serverless)

32. Cadeia de suprimentos e CI/CD​

  • NPM Security (interpreter)
  • Dependency Graph & SBOM Best Practices, Vulnerable Dependency Management (interpreter)

33. Segredos e configuração​

O gerenciamento de segredos é operacional: cofres, CI/CD, configuração de nuvem e rotação. A única faceta no nível do código (um segredo fixo no código-fonte) é uma varredura determinística, não uma especialização de risco. Movido para "Fora do escopo".

34. Processo, design e governança​

A proteção da privacidade do usuário é questão de política e de design (minimização de dados, transparência e retenção), não uma superfície no código que uma especialização defenda. Movido para "Fora do escopo".

35. Pagamentos e conformidade​

  • Secure Integration of Third-Party Payment Gateways (payment)

36. Sistemas embarcados, IoT e domínios especializados​

A segurança automotiva e a de drones são domínios de sistemas embarcados (barramento CAN, firmware OTA, integridade de sensores e rádio, acesso físico), e não o código-fonte de aplicações web e APIs que o Lagune audita. Movido para "Fora do escopo".

Fora do escopo (sem superfície no código)​

Estes itens não são terreno de especializações e não têm checkbox: são governança, processo, hardening operacional ou uso de frameworks, sem uma superfície única no código que uma especialização por superfície defenda. O valor deles para a segurança é real, mas está no processo e na arquitetura (ou, no caso de um framework, na skill da própria linguagem), e não em uma defesa que este catálogo entrega. Aparecem como referência, não como trabalho a fazer.

  • Authorization Regression Testing, Authorization Testing Automation
  • JAAS
  • Denial of Service, Denial of Service
  • HTTP/2 Reset Attack
  • Traffic flood
  • Web Service Amplification Attack (amplificação via SOAP e WS-Addressing, uma variante operacional de DoS sem superfície no código)
  • Cash Overflow
  • Spyware, Trojan Horse (malware no usuário final, não uma superfície no código do projeto auditado. A faceta de entrega pelo navegador fica em browser)
  • REST Security, REST Assessment
  • Web Service Security
  • Cloud Architecture Security (design e trade-offs: IAM versus URLs assinadas, VPCs públicas e privadas, fronteiras de confiança e responsabilidade compartilhada. Ao contrário de container, não tem uma configuração concreta que uma especialização verifique)
  • Infrastructure as Code Security (apesar do nome, trata do processo de SDLC e das ferramentas para gerenciar IaC: plugins de IDE, análise estática, varredura de imagens, CI/CD e assinatura. Não oferece um padrão inseguro a converter em forma segura dentro de um arquivo Terraform ou CloudFormation)
  • Kubernetes Security (apenas a parte de administração do cluster: RBAC, etcd, API server e admission. A parte de workloads e Pods está no escopo em container)
  • Network Segmentation (arquitetura de rede e política de firewall)
  • Subdomain Takeover Prevention (ciclo de vida e monitoramento de DNS, não código)
  • Secrets Management (cofres, CI/CD e rotação. A faceta do segredo fixo no código é uma varredura determinística, não uma especialização de risco)
  • C-Based Toolchain Hardening (flags de compilador, linker e build, sem um sink no código-fonte)
  • Microservices Security, Microservices based Security Arch Doc
  • Zero Trust Architecture
  • CI/CD Security, GitHub Actions Security
  • Software Supply Chain Security
  • Error Handling, Full Path Disclosure (configuração global do tratamento de erros em cada stack. O vazamento é a mesma exposição que o tratamento de erros já rege)
  • Abuse of Functionality, Business Logic Security, Abuse Case (historical) (design específico da aplicação, sem um sink único no código)
  • User Privacy Protection (minimização de dados, transparência e política de retenção)
  • Top 10 Automotive Security Vulnerabilities, Drone Security (domínios de sistemas embarcados, como barramento CAN, firmware OTA e integridade de sensores e rádio, e não código-fonte web ou de APIs)
  • Mobile Application Security (hardening das plataformas Android e iOS, como armazenamento, biometria, pinning e dados pessoais. Não tem uma superfície única no código, e a faceta de carregamento de código não confiável foi para interpreter)
  • Threat Modeling, Threat Modeling (community page)
  • Attack Surface Analysis
  • Secure Product Design
  • Secure Code Review
  • Virtual Patching
  • Vulnerability Disclosure
  • Legacy Application Management
  • Security Terminology

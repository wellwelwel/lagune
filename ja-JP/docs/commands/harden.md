# /lagune-harden: コードにセキュリティ修正を適用する

> 計画の修正を、安全に 1 つずつコードへ適用します。

正規 URL: https://lagune.ai/ja-JP/docs/commands/harden
言語: ja-JP
原文: https://lagune.ai/docs/commands/harden
最終更新日: 2026-11-05

🔧 計画の修正を、安全に 1 つずつコードへ適用します。

## 実行方法

**すべて適用**

```prompt
/lagune-harden
```

**パスを指定**

```prompt
/lagune-harden src/routes/upload.ts
```

**優先度で指定**

```prompt
/lagune-harden 緊急と重要
```

## 仕組み

各修正は計画の段階ですでに決まっているので、harden はそれを適用するだけです。コードに手を加える唯一のフェーズなので、慎重に進めます：すべての変更をレビューしやすく保つために修正は 1 つずつ適用し、修正を当てはめるために対策を弱めることも決してありません。たとえば、アップロードの修正は次のようになります：

- **ファイルのアップロード**（ステータス：**Applied**）
  - _変更内容_：ファイルの実際の種類とサイズを確認し、想定外のものはすべて拒否し、保存時に名前を変更し、コードとして実行できない場所に保存します。
  - _変更箇所_：`handleUpload` 関数と、そこから呼び出しているストレージのヘルパーです。

修正を完全に適用できない場合、harden は安全にできる範囲だけを実施し、残りを **Partial** または **Blocked** としてマークして、未解決のまま残します。

**Applied は検証済みではない**

Applied は、まだ証明されたという意味ではありません。それを証明するのが [verify](https://lagune.ai/ja-JP/docs/commands/verify) の役割です。

**ヒント**

- 計画の結果だけを土台にしています。計画にない修正やファイルがある場合は、先にそれを対象に `/lagune-plan` を実行するよう案内します。
- 再実行すると記録を現状と照合して更新し、元に戻された変更は外れ、新たに適用した修正が加わります。
- 堅牢化の記録は `.lagune/memory/harden.md` にあります。

**plan に依存し、コードを変更する**

harden は [`/lagune-plan`](https://lagune.ai/ja-JP/docs/commands/plan) を土台にしています。コードを変更する唯一のフェーズです。

## 次のステップ

各修正が有効であることを証明しましょう：[`/lagune-verify`](https://lagune.ai/ja-JP/docs/commands/verify)。

## よくある質問

### /lagune-harden はコードを変更しますか？

はい。コードに手を加える唯一のフェーズで、計画の修正を 1 つずつ適用します。

### Applied、Partial、Blocked はどういう意味ですか？

Lagune が各修正について記録するステータスです。Applied は修正が完了したこと、Partial は一部だけ完了したこと、Blocked は適用できなかったことを意味します。Applied は、まだ証明されたという意味ではありません。

### Lagune は確認なしで修正を適用しますか？

編集に承認が必要かどうかを決めるのは Lagune ではなく、使っているエージェントと、それを実行する権限モードです。Lagune 自体は独自の確認ステップを追加しません。それでも、修正を通すために対策を弱めることは決してなく、修正が charter のルールと衝突する場合は、作業を止めて先に知らせます。

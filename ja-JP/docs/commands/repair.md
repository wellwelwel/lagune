# /lagune-repair: 検出事項の壊れた追跡を修復する

> ファイル名の変更や移動で Lagune の追跡が混乱したときに、チェーンを修復します。

正規 URL: https://lagune.ai/ja-JP/docs/commands/repair
言語: ja-JP
原文: https://lagune.ai/docs/commands/repair
最終更新日: 2026-11-03

🧰 ファイル名の変更や移動でチェーンが混乱したときに、それを修復します。

**内部メンテナンス用で、セキュリティのフェーズではない**

repair は、順に進むフローの 6 番目のフェーズではありません。その役割は、追跡の整合性を保つことです。

```prompt
# 入力は受け取らず、常にチェーン全体を修復します
/lagune-repair
```

## 仕組み

detect の各検出事項は 1 つの追跡項目で、plan、harden、verify に引き継がれます。各フェーズはその項目を処理し、名前で改めて報告します。この名前はすべての成果物でまったく同じ表記のセクションタイトルとして書かれ、全体を通じてその項目の識別子になります。

追跡が保持する情報のうち、変わりうるのは項目が指すファイルパスだけです。これらのパスはほかのどこにも保存されないため、ファイル名の変更や移動で関連付けが切れるのはそこだけで、食い違う 2 つのコピーが生まれることはありません。そうなったとき、repair は追跡マップ（`.lagune/tracking.json`）を修正し、ファイル名が変わっても項目を正しく識別できるようにします。repair は成果物と追跡マップを読み、ソースコードは名前が変わったファイルの新しいパスを知るためだけに読みます。セキュリティに関する内容を書くことは決してありません。

同じ処理の中で、すべての記録をそれぞれのテンプレートと照合してずれを報告し、ずれごとに修正を担うフェーズを示します。

**ヒント**

- コードにも文章の成果物にも手を加えず、追跡だけを扱います。
- 手動で実行することはほとんどありません。チェーンの不整合に気づいたフェーズが代わりに repair を実行し、そのまま作業を続けます。
- repair が管理する追跡は `.lagune/tracking.json` にあります。手動では編集しない内部状態です。

# /lagune-detect: システムとそのリスクを洗い出す

> コードを読み取り、システムが何をしているのか、どこにリスクがあるのかを洗い出します。

正規 URL: https://lagune.ai/ja-JP/docs/commands/detect
言語: ja-JP
原文: https://lagune.ai/docs/commands/detect
最終更新日: 2026-11-04

🔬 システムが実際に何をしているのか、どこにリスクがあるのかを突き止めます。

detect はコードを読み取り、実際に見つけたものだけを、後続のフェーズが必要とする根拠とともに記録します。根幹となる指針は、創作ではなく検出です。

## 実行方法

**フルスキャン**

```prompt
/lagune-detect
```

**パスを指定**

```prompt
/lagune-detect src/routes/ src/auth.ts
```

**懸念を伝える**

```prompt
/lagune-detect 顧客データが外部に漏れることがないか確認してください
```

## 洗い出す内容

**Lagune** はコードを読み取り、見つけたものを洗い出します。各検出事項には、それが何か、なぜ重要か、そしてその根拠が含まれます。たとえば：

- **ファイルのアップロード**：システムがユーザーからファイルを受け付けています。
  - _重要な理由_：画像を装ったファイルに、悪意のあるコードが隠されているおそれがあります。
  - _根拠_：`POST /upload` のハンドラーが、ファイルの実際の種類を確認せず、クライアントが送ってきた MIME タイプをそのまま信用しています。
- **ログインとセッション**：ユーザーはサインインして自分のアカウントにアクセスします。
  - _重要な理由_：セッションの扱いが甘いと、アカウントが他人に乗っ取られるおそれがあります。
  - _根拠_：セッションを発行するロジックで、有効期限を設定しないままセッションが発行されています。

その過程で、detect はプロジェクトの [カタログ](https://lagune.ai/ja-JP/docs/catalog) にあるすべての専門知識をコードと照らし合わせて判定し、前提となるコンテキストがコードに存在するものを適用して、**Applied specializations** の下に記録します。harden と verify は、このリストを再利用します。

こうして、システムが何をしていて、どこにリスクがあるのかを示す明確なマップが手に入り、次のステップですぐに対処できます。

**ヒント**

- 再実行するとマップが更新され、解決済みの検出事項は外れ、新しい検出事項が加わります。
- detect のマップは `.lagune/memory/detect.md` にあります。

## よくある質問

### /lagune-detect は何をしますか？

コードを読み取り、システムが何をしているのか、どこにリスクがあるのかを洗い出し、実際に見つけたものだけを記録します。指針は、創作ではなく検出です。

### Lagune の検出事項とは何ですか？

検出事項とは、検出されたリスク 1 件分のことで、それが何か、なぜ重要か、コード上の根拠を含みます。plan、harden、verify が引き継いでいく、追跡の単位です。

### detect のマップはどこに保存されますか？

.lagune/memory/detect.md に保存されます。

### detect はどの専門知識を使いますか？

プロジェクトのカタログにあるすべての専門知識が、コードと照らし合わせて判定されます。detect は前提となるコンテキストが存在するものを適用し、Applied specializations の下に記録します。

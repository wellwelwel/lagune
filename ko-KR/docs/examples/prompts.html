Lagune 프롬프트 예시: Blue Team 흐름 자동화

바로 복사해 쓸 수 있는 Lagune 프롬프트 모음입니다. 읽기 전용 스캔, 전체 Blue Team 흐름, 제로 트러스트 감사는 물론, 커밋, 브랜치나 PR의 diff, 실제 보안 사고로 범위를 좁힌 탐지까지 담았습니다.

AI 에이전트에 그대로 붙여 넣어 바로 쓸 수 있는 Lagune 프롬프트입니다.

💧 간단 스캔​

Blue Team 흐름을 실행하거나 Lagune의 추적에 기록하지 않고, 에이전트가 스스로 코드를 읽어 모든 결함을 수정 방법과 함께 보고하는 읽기 전용 스캔입니다.

팁

계획 모드에서, 보안 원칙(/lagune-charter)을 정해 둔 상태로 사용하면 더 잘 작동합니다.

  • 🪼 기본
  • 🐬 멀티 에이전트
항목장단점수준
작업량에이전트 하나가 스캔과 보고를 맡음. 서브에이전트 없음.
소요 시간짧음. 읽기 전용으로 한 번 훑을 뿐, 아무것도 적용하지 않음.
토큰 사용량보통 수준, 컨텍스트 공유. 스캔 전체가 하나의 컨텍스트에서 실행됨.
/lagune 너는 방어 보안에 깊은 전문성을 갖춘 사이버 보안 연구자이고, Lagune을 활용해 지식과 정확도를 높이고 있어.

워크스페이스를 스스로 스캔하고, 찾은 결함마다 구체적인 수정 방법을 함께 제시해 줘. 이건 Blue Team 흐름이 아니라 독립적인 스캔이니까, detect, plan, harden, verify는 실행하지 말고 Lagune의 추적에도 아무것도 기록하지 마.

마지막으로, 찾은 결함을 빠짐없이 나열하고 각각 심각도와 구체적인 수정 방법을 붙여 줘.
항목장단점수준
작업량파일마다 서브에이전트 하나. 코드베이스 크기에 맞춰 규모를 조정.
소요 시간파일별로 병렬 처리한 뒤 보고서 하나로 병합. 여전히 읽기 전용.
토큰 사용량더 많지만 격리됨. 서브에이전트마다 각자의 컨텍스트에서 스캔.
/lagune 너는 Lagune을 활용해 경로를 나열하고, 경로마다 서브에이전트를 하나씩 실행하고, 그 보고서를 병합하는 사이버 보안 오케스트레이터야(모든 내용은 서브에이전트가 읽어).

현재 프로젝트 크기에 맞춰 작업을 서브에이전트에게 나눠 맡겨야 해. 코드베이스가 클수록 더 많은 서브에이전트를 모두 병렬로 실행하고, 각각에게 아래 프롬프트를 전달해 줘:

```prompt
/lagune 너는 방어 보안에 깊은 전문성을 갖춘 사이버 보안 연구자이고, Lagune을 활용해 지식과 정확도를 높이고 있어.

<path> 경로를 스스로 스캔하고, 찾은 결함마다 구체적인 수정 방법을 함께 제시해 줘. 이건 Blue Team 흐름이 아니라 독립적인 스캔이니까, detect, plan, harden, verify는 실행하지 말고 Lagune의 추적에도 아무것도 기록하지 마.

마지막으로, <path> 경로에서 찾은 결함을 빠짐없이 나열하고 각각 심각도와 구체적인 수정 방법을 붙여 줘.
```

마지막으로, 모든 서브에이전트의 보고서를 결함과 수정 방법을 우선순위대로 정리한 목록 하나로 병합해 줘.
경고

간단 스캔은 범위를 좁히지 않은 광범위한 프롬프트 하나로 이루어지므로, 에이전트에 따라 거부하거나 중간에 멈출 가능성이 더 높습니다. 사용하는 에이전트가 응하지 않으면 대신 아래의 전체 Blue Team 흐름을 실행하세요. 범위를 좁혀 한 단계씩 진행하므로 차단될 가능성이 훨씬 낮습니다.

🌊 자동 Blue Team 감사 흐름​

전체 명령어 흐름을 처음부터 끝까지 실행합니다.

  • 🪼 기본
  • 🐋 멀티 에이전트(심층 스캔)
항목장단점수준
작업량코드베이스 크기와 관계없이 에이전트 하나. 서브에이전트 없음.
소요 시간보통이지만 큰 코드베이스에서는 덜 꼼꼼함. 각 명령어를 차례로 한 번씩 실행.
토큰 사용량더 적지만 격리 수준은 낮음. 모든 명령어가 같은 컨텍스트를 공유.
다음 명령어를 하나씩 차례로 실행해 줘: `/lagune-charter`, `/lagune-detect`, `/lagune-plan`, `/lagune-harden`, `/lagune-verify`.

## 반복

`/lagune-verify` 명령어가 수정을 하나라도 거부하면, 모든 발견 사항이 제대로 해결될 때까지 `/lagune-harden` 명령어와 `/lagune-verify` 명령어를 차례로 반복해 줘.
항목장단점수준
작업량서브에이전트 수를 코드베이스 크기에 맞춰 조정.
소요 시간더 길지만 더 꼼꼼함. 여러 서브에이전트를 실행해 발견 사항의 탐지, 계획, 보안 강화를 병렬로 진행.
토큰 사용량더 많지만 더 안전함. 서브에이전트마다 편향 없는 독립된 컨텍스트를 가짐.
다음 명령어를 각각 서브에이전트 하나에 맡겨, 한 번에 하나씩 실행해 줘(백틱 없이 명령어만 전달해):

서브에이전트 1 프롬프트: `/lagune-charter`
서브에이전트 2 프롬프트: `/lagune-detect`
서브에이전트 3 프롬프트: `/lagune-plan`
서브에이전트 4 프롬프트: `/lagune-harden`
서브에이전트 5 프롬프트: `/lagune-verify`

`/lagune-detect`, `/lagune-plan`, `/lagune-harden`, `/lagune-verify` 명령어에서는 현재 프로젝트 크기에 맞춰 작업을 서브에이전트에게 나눠 맡겨야 해. 코드베이스가 클수록 더 많은 서브에이전트를 실행해야 해. 예를 들면:

```prompt
/lagune-detect <path>
```

```prompt
/lagune-plan <finding>
```

```prompt
/lagune-harden <finding>
```

```prompt
/lagune-verify <finding>
```

- 같은 명령어를 맡은 여러 에이전트는 병렬로 실행해 줘.
- 모든 `/lagune-detect` 서브에이전트가 끝나면 다음을 실행해 줘:

```prompt
/lagune-detect 서로 같은 발견 사항을 하나로 합쳐 줘. 새 발견 사항을 찾거나 코드베이스를 다시 스캔하지는 마.
```

## 반복

`/lagune-verify` 명령어가 수정을 하나라도 거부하면, 모든 발견 사항이 제대로 해결될 때까지 `/lagune-harden` 명령어와 `/lagune-verify` 명령어를 차례로 반복해 줘.

🪄 범위를 지정한 탐지​

프로젝트 전체 대신 일부에만 /lagune-detect 명령어를 실행하세요. 커밋이든 풀 리퀘스트든 실제 상황이든, 범위를 평소 말하듯 설명하면 그 안에서 보안과 관련된 발견 사항만 파악합니다.

팁

여기서 탐지한 결과는 모두 일반 발견 사항이므로, 해당 항목으로만 범위를 한정해 /lagune-plan, /lagune-harden, /lagune-verify 명령어로 바로 이어 갈 수 있습니다.

  • 📌 특정 커밋 이후
  • 🔀 브랜치 또는 PR diff
  • ⛑️ 보안 사고 이후

새로 쌓인 커밋만 따로 보안 점검을 하되, 범위는 그 커밋들이 변경한 부분으로 한정하세요. 예를 들면 다음과 같습니다:

/lagune-detect 커밋 `a1b2c3d` 이후로 바뀐 모든 부분으로 탐지 범위를 한정해 줘.

풀 리퀘스트를 병합하기 전에, 그 diff로만 범위를 좁혀 보안 관점에서 검토하세요. 예를 들면 다음과 같습니다:

/lagune-detect 이 브랜치가 `main` 브랜치와 비교해 새로 들여온 변경 사항으로 탐지 범위를 한정해 줘.

무슨 일이 있었는지 직접 설명하세요. Lagune은 플래그가 아니라 상황 자체를 읽고, 이를 목표가 분명한 탐색으로 바꿉니다. 예를 들면 다음과 같습니다:

/lagune-detect 몇 주 전에 우리 사이트에서 데이터 유출이 있었어. 정확히 어떻게 일어났는지는 모르겠고, 데이터가 다시 샐 수 있는 구멍이 아직 남아 있을까 봐 걱정돼. 코드를 꼼꼼히 살펴보고, 민감한 데이터를 읽거나 저장하거나 노출하는 곳이라면 어디든 집중해서, 아직 데이터가 빠져나갈 통로가 될 만한 건 전부 파악해 줘. 훈련이 아니라 실제 사고로 다뤄 줘.

🚨 제로 트러스트 감사​

워크스페이스 전체와 모든 의존성을 적대적인 것으로 간주합니다. 인터프리터, 네트워크 호출, 인코딩된 페이로드, 그리고 스캐너를 피하려고 예상치 못한 곳에 숨겨 둔 코드를 찾아낸 뒤, 프로젝트를 안전하게 사용할 수 있는지 go/no-go 판정을 내립니다.

프롬프트는 프로젝트의 카테고리와 관계없이 이 감사에 필요한 전문 지식을 직접 불러옵니다. 그 밖에 /lagune 명령어가 카탈로그에서 찾아 쓰는 전문 지식까지 활용하려면, 프로젝트가 OWASP, AI/LLM, 그리고 스택에 해당하는 카테고리(예: JavaScript, Python 등)를 사용하도록 하세요:

npx lagune write add --categories owasp ai javascript

저장소에 포함된 .gitignore 파일과 설정 때문에 검사기가 일부 파일을 보지 못할 수 있으므로, checkers 블록을 .lagune/configs.json 파일에 넣어 모든 것을 스캔하도록 설정하세요. 저장소에 이미 들어 있는 블록이 있다면 이 블록으로 바꾸세요:

{
  "checkers": { "gitignore": false }
}
위험

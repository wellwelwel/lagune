# /lagune-detect: 시스템과 위험 파악하기

> 코드를 읽고 시스템이 무엇을 하는지, 위험이 어디에 있는지 파악합니다.

표준 URL: https://lagune.ai/ko-KR/docs/commands/detect
언어: ko-KR
원문: https://lagune.ai/docs/commands/detect
마지막 업데이트: 2026-11-04

🔬 시스템이 실제로 무엇을 하는지, 위험이 어디에 있는지 알아보세요.

detect 단계는 코드를 읽고 실제로 찾은 것만, 이후 단계에 필요한 근거와 함께 기록합니다. 이 단계의 가장 중요한 지침은 지어내지 않고 탐지하는 것입니다.

## 사용법

**전체 스캔**

```prompt
/lagune-detect
```

**경로 지정하기**

```prompt
/lagune-detect src/routes/ src/auth.ts
```

**우려 사항 설명하기**

```prompt
/lagune-detect 고객 데이터가 절대 노출되지 않는지 확인해 줘
```

## 파악하는 내용

**Lagune**은 코드를 읽고 찾은 것을 파악합니다. 각 발견 사항은 무엇이 문제인지, 왜 중요한지, 근거가 무엇인지를 담습니다. 예를 들면 다음과 같습니다.

- **파일 업로드**: 시스템이 사용자에게서 파일을 받습니다.
  - _중요한 이유_: 이미지로 위장한 파일에 악성 코드가 숨어 있을 수 있습니다.
  - _근거_: `POST /upload` 핸들러가 파일의 실제 형식을 확인하지 않고 클라이언트가 보낸 MIME 타입을 그대로 신뢰합니다.
- **로그인과 세션**: 사용자가 로그인해 자기 계정에 접근합니다.
  - _중요한 이유_: 세션 처리가 허술하면 다른 사람이 계정을 탈취할 수 있습니다.
  - _근거_: 세션 발급 로직에서 만료 시간을 설정하지 않은 채 세션을 발급합니다.

이 과정에서 detect 단계는 프로젝트 [카탈로그](https://lagune.ai/ko-KR/docs/catalog)의 모든 전문 지식을 코드와 대조해 판정을 내리고, 해당 컨텍스트가 코드에 있는 전문 지식을 적용한 뒤, harden과 verify 단계가 다시 사용하는 목록인 **Applied specializations** 항목에 기록합니다.

이렇게 해서 시스템이 무엇을 하고 위험이 어디에 있는지 보여 주는 명확한 맵이 생기며, 다음 단계에서 바로 활용할 수 있습니다.

**팁**

- 다시 실행하면 맵이 갱신되어, 해결된 발견 사항은 빠지고 새 발견 사항이 추가됩니다.
- 탐지 맵은 `.lagune/memory/detect.md` 파일에 있습니다.

## 자주 묻는 질문

### /lagune-detect 명령어는 무엇을 하나요?

코드를 읽고 시스템이 무엇을 하는지, 위험이 어디에 있는지 파악하며, 실제로 찾은 것만 기록합니다. 지어내지 않고 탐지하는 것이 원칙입니다.

### Lagune에서 발견 사항이란 무엇인가요?

발견 사항은 탐지된 위험 하나를 말하며, 무엇이 문제인지, 왜 중요한지, 코드상의 근거를 담습니다. plan, harden, verify 단계가 이어서 다루는 추적 단위입니다.

### 탐지 맵은 어디에 저장되나요?

.lagune/memory/detect.md 파일에 저장됩니다.

### detect 단계는 어떤 전문 지식을 사용하나요?

프로젝트 카탈로그에 있는 모든 전문 지식을 코드와 대조해 판정합니다. detect 단계는 해당 컨텍스트가 있는 전문 지식을 적용하고 Applied specializations 항목에 기록합니다.

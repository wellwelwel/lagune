# /lagune-repair: 깨진 발견 사항 추적 복구하기

> 파일 이름이 바뀌거나 파일이 이동해 Lagune의 추적이 꼬였을 때 체인을 복구합니다.

표준 URL: https://lagune.ai/ko-KR/docs/commands/repair
언어: ko-KR
원문: https://lagune.ai/docs/commands/repair
마지막 업데이트: 2026-11-04

🧰 파일 이름이 바뀌거나 파일이 이동해 체인이 꼬였을 때 복구합니다.

**보안 단계가 아닌 내부 유지 관리**

repair는 순서대로 진행되는 흐름의 여섯 번째 단계가 아닙니다. repair의 역할은 추적의 일관성을 유지하는 것입니다.

```prompt
# 입력은 받지 않으며, 항상 체인 전체를 복구합니다
/lagune-repair
```

## 작동 방식

detect 단계의 각 발견 사항은 하나의 추적 항목이며, plan, harden, verify 단계가 이를 이어받아 각자 처리하고 이름으로 다시 보고합니다. 이 이름은 모든 산출물에서 똑같은 섹션 제목으로 쓰이며, 처음부터 끝까지 그 항목의 식별자 역할을 합니다.

추적이 저장하는 정보 중 바뀔 수 있는 것은 항목이 가리키는 파일 경로뿐입니다. 이 경로는 다른 곳에는 저장되지 않으므로, 파일 이름이 바뀌거나 파일이 이동해도 연결이 끊기는 곳은 이곳 하나뿐이며, 서로 어긋난 두 사본이 생기는 일은 없습니다. 그런 일이 생기면 repair가 추적 맵(`.lagune/tracking.json`)을 바로잡아, 이름이 바뀌어도 항목의 식별자가 유지되게 합니다. repair는 산출물과 추적 맵을 읽고, 소스 코드는 이름이 바뀐 파일의 새 경로를 알아낼 때만 읽으며, 보안 관련 내용을 직접 작성하는 일은 없습니다.

같은 실행에서 모든 기록 산출물을 각 템플릿과 대조해 어긋난 부분을 보고하고, 각 부분을 바로잡을 단계를 알려 줍니다.

**팁**

- 코드도, 글로 된 산출물도 건드리지 않고 추적만 다룹니다.
- 직접 실행할 일은 거의 없습니다. 체인이 일관되지 않다는 것을 알아챈 단계가 대신 repair를 실행하고 작업을 이어 갑니다.
- repair가 관리하는 추적은 `.lagune/tracking.json` 파일에 있으며, 직접 편집할 일이 없는 내부 상태입니다.

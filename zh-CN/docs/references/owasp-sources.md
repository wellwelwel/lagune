# OWASP 来源

> 内置 OWASP 专项的知识从何而来，并对应到 OWASP 官方的攻击页面和 Cheat Sheet 页面。

规范链接: https://lagune.ai/zh-CN/docs/references/owasp-sources
语言: zh-CN
原文: https://lagune.ai/docs/references/owasp-sources
最后更新: 2026-11-03

本文档把 OWASP 的每个**攻击**（`www-community`）和每份 **Cheat Sheet**（`CheatSheetSeries`）对应到一个安全类别，并分别链接到它们的官方公开页面。在同一个类别中，等价的条目共用一行清单：针对同一风险的攻击和 Cheat Sheet 列在一起，用逗号分隔。没有直接对应项的条目单独占一行。

- 内容归功于 OWASP。攻击页面位于 `https://owasp.org/www-community/attacks/<attack>`，Cheat Sheet 位于 `https://cheatsheetseries.owasp.org/cheatsheets/<cheat>.html`。

## 31. 云、容器与基础设施

容器和工作负载的配置属于配置即代码，由开发者随应用一起发布（`Dockerfile`、Compose、Pod 的 `securityContext`），是 `harden` 能修复、`verify` 能证明的真实攻击面，因此在范围内。集群管理（RBAC、etcd、API server、准入控制、网络分段）属于运维人员的职责，仍不在范围内。

## 33. 密钥与配置

密钥管理属于运维范畴：密钥保管库、CI/CD、云配置、轮换。唯一涉及代码的部分（源码中硬编码的密钥）由确定性扫描负责，而不是风险专项。已移至"不在范围内"。

---

## 34. 流程、设计与治理

用户隐私保护属于策略和设计问题（数据最小化、透明度、保留期限），不是专项能够防御的代码攻击面。已移至"不在范围内"。

这些条目不属于专项的领域，也没有复选框：它们属于治理、流程、运维层面的加固或框架用法，没有单一的代码攻击面可供按攻击面划分的专项来防御。它们的安全价值是真实的，但体现在流程和架构中（对于框架，则体现在该语言自己的 skill 中），而不在这个目录提供的防御里。列在这里仅供参考，不是待办工作。

Lagune 提示词示例：自动化 Blue Team 流程

复制即用的 Lagune 提示词：只读扫描、完整的 Blue Team 流程和零信任审计，以及限定在某个 commit、分支或 PR diff，或真实安全事件上的检测。

复制即用的 Lagune 提示词，可以直接粘贴到你的 AI 智能体中。

💧 浅层扫描​

一次只读扫描：智能体自行阅读代码，报告每个缺陷并附上修复方案，既不运行 Blue Team 流程，也不写入 Lagune 的追踪记录。

提示

在规划模式下，并且已经定义了安全原则（/lagune-charter）时，效果更好。

  • 🪼 默认
  • 🐬 多智能体
方面权衡等级
工作量由一个智能体扫描并报告，不使用子智能体。
耗时快。只做一轮只读扫描，不应用任何修改。
Token 消耗中等，共享上下文。整个扫描在同一个上下文中运行。
/lagune 你是一名精通防御性安全的网络安全研究员，正在使用 Lagune 提升自己的知识和精准度。

自行扫描工作区，并为发现的每个缺陷配上具体的修复方案。这是一次独立扫描，不是 Blue Team 流程：不要运行 detect、plan、harden 或 verify，也不要向 Lagune 的追踪记录写入任何内容。

最后，列出你发现的所有缺陷，每个都附上严重程度和具体的修复方案。
方面权衡等级
工作量每个文件一个子智能体，数量随代码库规模调整。
耗时按文件并行，最后合并成一份报告。仍然只读。
Token 消耗较高，但相互隔离。每个子智能体在各自的上下文中扫描。
/lagune 你是一名网络安全编排者，使用 Lagune 枚举路径、为每个路径派发一个子智能体，并合并它们的报告（所有内容都由子智能体读取）。

你必须根据当前项目的规模把任务委派给子智能体：代码库越大，派发的子智能体就越多，全部并行运行，并给每个子智能体下面这段提示词：

```prompt
/lagune 你是一名精通防御性安全的网络安全研究员，正在使用 Lagune 提升自己的知识和精准度。

自行扫描 <path>，并为发现的每个缺陷配上具体的修复方案。这是一次独立扫描，不是 Blue Team 流程：不要运行 detect、plan、harden 或 verify，也不要向 Lagune 的追踪记录写入任何内容。

最后，列出 <path> 中的所有缺陷，每个都附上严重程度和具体的修复方案。
```

最后，把所有子智能体的报告合并成一份按优先级排列的缺陷与修复清单。
注意

快速扫描是一条宽泛、不限定范围的提示词，因此有些智能体更容易拒绝执行或中途停止。如果你的智能体不配合，请改为运行下面完整的 Blue Team 流程：它的各个阶段范围明确、循序渐进，被拦下的可能性要小得多。

🌊 自动 Blue Team 审计流程​

从头到尾运行 完整的命令流程。

  • 🪼 默认
  • 🐋 多智能体（深度扫描）
方面权衡等级
工作量一个智能体，不使用子智能体，与代码库规模无关。
耗时中等，但在大型代码库中不够全面。每条命令依次运行一次。
Token 消耗较低，但隔离性较差。所有命令共享同一个上下文。
依次执行以下命令：`/lagune-charter`、`/lagune-detect`、`/lagune-plan`、`/lagune-harden` 和 `/lagune-verify`。

## 循环

当 `/lagune-verify` 判定一项或多项修复未通过时，重复执行 `/lagune-harden`，再执行 `/lagune-verify`，直到所有发现项都得到妥善解决。
方面权衡等级
工作量子智能体的数量随代码库规模调整。
耗时较长，但更全面。会派发多个子智能体，并行地检测、规划和加固发现项。
Token 消耗较高，但更安全。每个子智能体都有自己独立的上下文，不受偏见影响。
把以下每条命令分别交给一个子智能体执行，一次一个（不带反引号，只写命令本身）：

子智能体 1 的提示词：`/lagune-charter`
子智能体 2 的提示词：`/lagune-detect`
子智能体 3 的提示词：`/lagune-plan`
子智能体 4 的提示词：`/lagune-harden`
子智能体 5 的提示词：`/lagune-verify`

在 `/lagune-detect`、`/lagune-plan`、`/lagune-harden` 和 `/lagune-verify` 命令中，你必须根据当前项目的规模把任务委派给子智能体：代码库越大，派发的子智能体就越多。例如：

```prompt
/lagune-detect <path>
```

```prompt
/lagune-plan <finding>
```

```prompt
/lagune-harden <finding>
```

```prompt
/lagune-verify <finding>
```

- 同一条命令的多个智能体应并行派发。
- 所有 `/lagune-detect` 子智能体完成后，执行：

```prompt
/lagune-detect 合并等价的发现项。不要检测新的发现项，也不要重新扫描代码库。
```

## 循环

当 `/lagune-verify` 判定一项或多项修复未通过时，重复执行 `/lagune-harden`，再执行 `/lagune-verify`，直到所有发现项都得到妥善解决。

🪄 限定范围的检测​

让 /lagune-detect 只针对项目的一部分，而不是整个项目。用日常语言描述范围（某个 commit、某个 pull request 或一个真实情况），它就只找出该范围内与安全相关的发现项。

提示

它在这里检测到的都是普通发现项，因此你可以直接把它们带入 /lagune-plan、/lagune-harden 和 /lagune-verify，范围只限于这些条目。

  • 📌 自某个 commit 起
  • 🔀 分支或 PR diff
  • ⛑️ 安全事件之后

为一批新提交单独做一次安全检查，范围只限于它们改动的内容，例如：

/lagune-detect 把检测范围限定在自 commit `a1b2c3d` 以来改动的所有内容。

在 pull request 合并之前审查它的安全性，范围只限于它的 diff，例如：

/lagune-detect 把检测范围限定在这个分支相对 `main` 引入的改动。

用你自己的话描述发生了什么。Lagune 读的是情况本身，而不是某个选项，并会把它变成一次有针对性的排查，例如：

/lagune-detect 几周前我们的网站发生了数据泄露。我不清楚具体是怎么发生的，担心还有漏洞没堵上，可能再次泄露数据。请仔细检查代码，重点关注所有读取、存储或暴露敏感数据的地方，把任何仍可能让数据流出的途径都梳理出来。请把这当作真实的安全事件，而不是演练。

🚨 零信任审计​

把整个工作区和每个依赖都视为敌对的：它会搜寻解释器、网络调用、编码过的 payload，以及藏在意想不到的地方、企图躲过扫描器的代码，最后给出 go/no-go 判定结果，说明这个项目能否安全使用。

无论项目设置了哪些类别，这些提示词都会直接加载这项审计所依赖的专项。至于 /lagune 从目录中匹配的其余专项，请确保项目使用了 OWASP、AI/LLM，以及项目技术栈对应的类别（例如 JavaScript、Python 等）：

npx lagune write add --categories owasp ai javascript

仓库自带的 .gitignore 文件和配置可能会把文件藏起来，让检查器看不到，因此请把 checkers 块写进 .lagune/configs.json，设置为 扫描全部内容，如果仓库自带了这个块，就替换掉它：

{
  "checkers": { "gitignore": false }
}
危险

在本地环境中运行来源不可信的项目时要格外小心。请使用隔离环境，例如沙箱（推荐）、虚拟机或类似环境，防止恶意代码影响你的系统。

  • 🪼 默认
  • 🐋 多智能体（深度扫描）
方面权衡等级
工作量由一个智能体扫描整个工作区，不使用子智能体。
耗时中等。一个智能体依次检查代码及其依赖。
Token 消耗中等，但共享上下文。专项、代码和依赖都加载到同一个上下文中。
/lagune 你是一名精通零信任防御性安全的网络安全研究员，正在使用 Lagune 提升自己的知识和精准度。

梳理整个工作区，把它当作不可信的来源和潜在的恶意范围。所有解释器、fetch、base64 等都必须视为潜在威胁。

把分析扩展到依赖和子依赖：项目可能会把恶意代码藏在意想不到的地方，以躲过扫描器。

必须加载的专项（使用 `npx lagune read catalog <name>` 逐个加载）：

- interpreter
- secrets
- llm
- path

需要明确的是：每个梳理出的漏洞都必须视为潜在威胁，没有例外。

最后，给出判定结果：这个项目对我来说是否安全可信、能否使用。
方面权衡等级
工作量每个文件一个子智能体，数量随代码库规模调整。
耗时较长，但更全面。并行扫描各个文件，最后合并成一个判定结果。
Token 消耗最高，但最安全。每个子智能体都在自己独立的上下文中读取专项。
/lagune 你是一名网络安全编排者，使用 Lagune 枚举文件、为每个文件派发一个子智能体并生成报告（所有内容都由子智能体读取）。

为每个文件派发一个子智能体，全部并行运行，并给每个子智能体下面这段提示词，范围限定在它负责的文件：

```prompt
/lagune 你是一名精通零信任防御性安全的网络安全研究员，正在使用 Lagune 提升自己的知识和精准度。

把 <file> 视为不可信的来源和潜在的恶意范围。所有解释器、fetch、base64 等都必须视为潜在威胁。

把分析扩展到 <file> 导入的所有内容，包括依赖和子依赖，恶意代码可能藏在其中以躲过扫描器。

每个子智能体都必须加载的专项（使用 `npx lagune read catalog <name>` 逐个加载）：

- interpreter
- secrets
- llm
- path

需要明确的是：每个梳理出的漏洞都必须视为潜在威胁，没有例外。

最后，给出判定结果：这个项目对我来说是否安全可信、能否使用。
```

最后，把所有子智能体的报告合并成一个最终判定结果。
